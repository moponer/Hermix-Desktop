# 界面重设计：纸 · 案 · 墨（Paper · Desk · Ink）

> 2026-09-28 · 面向 Hermes Desktop 全部界面
> 目标：去掉"古板/死板/层次不清"，建立一套有主张的、能长期盯着不累的视觉语言。

---

## 0. 一句话主张

**结果优先，过程按需；纸面阅读，案面操作，墨只属于"现在需要你看的东西"。**

现有的 agent 界面（Cursor / Cline / Devin / 各家开源）几乎都在做同一件事：把 agent 的
每一步思考、每一次工具调用、每一段命令输出都默认摊开在主流里，用一串等宽小卡片
制造"很忙碌"的观感。**我们反过来做**：默认只呈现"结论"和"一行状态"，过程永远可召出
但默认收起。这一条决定了下面所有视觉决策。

---

## 1. 诊断：为什么现在看起来古板、死板、层次不清

### 1.1 12 个 surface 挤在 12% 明度带里（主因）

亮色基线有 12 个背景令牌（`tokens.css:99-111`）：`bg-app / primary / secondary /
tertiary / quaternary / hover / active / card / card-hover / elevated / inset /
input / base`。把它们按明度排开：

| 令牌 | 值 | 相对亮度 |
|---|---|---|
| bg-primary / card / input | `#faf9f5` | ~98% |
| bg-base | `#f8f7f2` | ~97% |
| bg-secondary | `#f7f6f1` | ~96.5% |
| bg-app | `#f5f4ed` | ~95% |
| chat-tool-bg | `#f2f0e8` | ~94% |
| bg-tertiary / hover | `#efece4` | ~92.5% |
| bg-inset | `#ebe8df` | ~90.5% |
| bg-active | `#e6e3d8` | ~88% |
| bg-quaternary | `#e2dfd5` | ~86% |

**问题**：全部是同一个暖米色相，全部挤在 98%→86% 的 12 个点里，且相邻两级只差
1-2% 亮度。人眼在同色相下要 ≥3% 明度差才读得出"这一层比那一层高"，所以
**卡片和背景在视觉上是同一块布**——层次根本不存在。

层次读不出来，设计就必然退回唯一可用的分隔手段：**到处画 1px 边框**。这就是
"古板"的真正来源——不是边框本身丑，是**用边框代替了本该由明度承担的层次**。
于是每个用户气泡、每张工具卡、每个面板、每个 chip 都成了"盒子"，满屏平行矩形，
这就是"死板"。

暗色同病：`dark.css:16-28` 十一个面全在 `#0b0b0b → #2c2c2c`（4%→17%）之间，且
**全部 R=G=B 纯中性**。纯灰没有色温，暗色界面失去"通透"感，只剩"水泥灰"。

### 1.2 两份平行 CSS 在打架，把每主题的场景色全部作废（代码 bug）

`components.css` 和 `components-layout.css` 各自定义了一份 `.app-shell /
.app-body / .pane / .titlebar`。`globals.css:12` 先引 layout，`main.tsx:17` 后引
`components.css`——**后引的赢**（同优先级）。结果：

| 类 | layout（被覆盖） | components.css（实际生效） |
|---|---|---|
| `.titlebar` bg | `var(--theme-bg-titlebar, …)` | `var(--color-bg-secondary)` |
| `.pane-left` bg | `var(--theme-bg-sidebar, …)` | `var(--color-bg-secondary)` |
| `.app-body` | 含 1 条 `@container` 规则 | 无（旧版写死 `minmax(0,480px)`） |

也就是说：**我们为每套主题精心设计的"标题栏/侧栏/对话区三段场景色"
（`--theme-bg-titlebar / --theme-bg-sidebar / --theme-bg-chat`）在标题栏和侧栏
上是死代码**——所有主题的标题栏和侧栏都塌缩成同一个通用灰米色。这就是"四套主题
看起来都一样、换主题像没换"的直接原因。

**这一条是 bug 不是审美，第一批必须先修。**

### 1.3 12 个背景名 = 没有深度语法

`app / primary / secondary / tertiary / quaternary / hover / active / card /
card-hover / elevated / inset / input / base` —— 这些名字描述的是"用途"不是
"高度"，组件写样式时无法知道"我该比背景高还是低"，只能凭手感挑，于是全应用
缺少一致的深度语义。这套命名本身就是层次混乱的语言学根源。

### 1.4 品牌橙和警告琥珀是同一个色系

`--color-accent: #c96442`（陶土橙）与 `--color-warning: #b45309`（琥珀）
色相差仅约 30°，明度接近。同一屏上"品牌强调"和"⚠ 需要注意"用几乎同一个颜色，
语义互相稀释；而工具运行态（`components.css:1240` `.tool-running`）又用了
warning，于是**"正在执行"和"品牌色"混成一片**。

### 1.5 聊天页：每一层都是一个盒子

- 用户气泡：底色 + 边框 + 圆角（`components.css:891-894`）
- 工具行：容器 + rail 竖线 + rail 圆点 + 折叠面板
- 审批卡：底色 + backdrop-filter + 双 inset 阴影（`components-prose.css:1507-1516`）
- 待办卡、compaction 卡、思考卡：各自独立卡片语言

一轮对话里有 5 种卡片语言在打架，读者无法建立"这是一类东西"的预期，只能靠
边框和底色硬分——于是又回到满屏盒子。

## 2. 墨水屏小说为什么舒服：五条可迁移原则

Kindle / 电子墨阅读器是**长期注视型界面**的极限优化样本，它的舒服不是"复古 styling"，
而是五件反潮流的事：

1. **低对比**：纸 ~92% 亮度 / 字 ~18% 亮度，对比约 12:1——不是 21:1。
   高对比会产生光晕（halation），久看眼干。**层次不靠"更亮"堆出来。**
2. **零彩色**：整屏只有黑与灰。任何颜色都是噪音，会把注意力从文字上拽走。
3. **层次全靠排版**：字号、字重、行距、字距、缩进——**没有一个靠颜色**。
4. **单列 + 稳定节奏**：一行 65-75 字符、行高 1.7-1.8、段间距恒定。
   眼睛沿着一条轴扫下来，不需要重新定位。
5. **Chrome 后退**：页码、边注、工具条全部退到背景层，**阅读平面是平的**。

**迁移结论（关键）**：不要把整个应用做成墨水屏——那会让工具型界面变得平庸。
正确的做法是**双平面语言**：

> **纸面（阅读）** 用墨水屏的克制：无边框、低对比、宽行距、纯排版分层。
> **案面（操作）** 用工具型的紧凑：中性灰、小圆角、1px 分隔线、控件密度高。
> **墨（强调）** 只给"现在需要你注意/决定"的东西，一屏最多出现一次。

这样既拿到了久看不累，又不会把 IDE 做成电子书。

## 3. 总体设计理念：纸 · 案 · 墨

### 3.1 三平面

```
┌─────────────────────────────────────────────┐
│  案面 Desk  ← 顶栏 / 侧栏 / 工具条 / 状态条    │  中性灰，紧凑，1px 分隔
│    ┌─────────────────────────────────────┐  │
│    │  纸面 Paper ← 对话正文 / 思考 / 总结  │  │  暖白，无边框，宽松排版
│    │                                      │  │
│    │   ┌──────────────────────────┐      │  │
│    │   │  墨 Ink ← 需要你决定的东西 │      │  │  唯一饱和色，全屏最多 1 处
│    │   └──────────────────────────┘      │  │
│    └─────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

### 3.2 六条铁律

| # | 铁律 | 判定标准（可测） |
|---|---|---|
| R1 | **深度只有 3 级**：纸（底）/ 案（面）/ 浮（overlay） | 全应用 surface 令牌 ≤ 5 个 |
| R2 | **相邻两层只用一个信号**：要么明度差，要么阴影+边框，二选一 | 出现"底色+边框+阴影"三件套 = 违规 |
| R3 | **饱和色是稀缺资源** | 单屏内 accent 元素 ≤ 3 个；语义色只用于语义 |
| R4 | **纸面上不画边框**，用留白和字重分层 | `.paper-*` 内 `border` 必须为 0 |
| R5 | **一个屏幕只有一件最亮的事** | 亮度/饱和度最高的那一处，就是当前该看的地方 |
| R6 | **过程默认收起** | 工具/思考/命令输出默认折叠，一行状态即可代表 |

### 3.3 密度规范

| 场景 | 规格 |
|---|---|
| 正文（纸面） | 14px / 行高 1.75 / measure 68ch（中文约 34 字/行） |
| 段间距 | 0.75em |
| 列表行 | 36px |
| 工具行 | 28px |
| 输入框 | min-height 44px（触达友好） |
| 代码 | 13px / 行高 1.6 / 等宽 |
| 圆角 | 控件 6px / 卡片 10px / 浮层 12px / 球 999px |

## 4. 令牌重构

### 4.1 亮色「暖纸」

```css
/* 面 —— 只有 4 级，相邻差 ≥ 3% 明度 */
--paper:        #f6f4ee;   /* 底：应用背景、对话区（暖纸，不用纯白） */
--desk:         #efede6;   /* 案：侧栏、顶栏、工具条（比纸低一档） */
--surface:      #fcfbf7;   /* 面：卡片、输入框、气泡（比纸亮 = 抬起） */
--overlay:      #ffffff;   /* 浮：弹窗、菜单、悬浮球（最亮 + 阴影） */

/* 分隔 —— 极低对比，只在必要时出现 */
--hairline:     #e6e3da;
--hairline-firm: #d6d2c6;

/* 文字 —— 4 级，主文字对比度 ~12:1（墨水屏原则，不追求 21:1） */
--ink-1: #33312d;   /* 正文 */
--ink-2: #5c5952;   /* 次要 */
--ink-3: #8a867c;   /* 元信息 */
--ink-4: #aca79b;   /* 占位/禁用 */

/* 墨 —— 品牌橙保持不变，但语义色必须与它拉开色相 */
--accent:  #c05a38;            /* 陶土橙：主行动/当前选中/品牌 */
--success: #2e7d53;            /* 绿 */
--warning: #9a7b0f;            /* 芥黄（从 #b45309 移开 40° 色相） */
--error:   #a83c3c;            /* 砖红（比现值更暗更钝，减少刺眼） */
--info:    #6b7a8a;            /* 冷灰蓝，仅用于"中性提示"，不再冒充灰 */
```

**关键改动方向与现状相反**：现在是"卡片比背景更暗/同色"（`bg-card #faf9f5` ==
`bg-primary`），所以卡片根本没抬起来。新方案是**卡片比背景更亮**（`#fcfbf7` >
`#f6f4ee`），"抬起"由明度方向统一承担，边框只留给同层分隔。

### 4.2 暗色「夜灯」

```css
--paper:   #131417;   /* 底：不用纯黑（纯黑 OLED 死黑 + 无层次） */
--desk:    #191a1e;   /* 案：比纸亮一档 */
--surface: #1e2024;   /* 面 */
--overlay: #26282d;   /* 浮 */

--hairline:      #26282c;
--hairline-firm: #34363c;

--ink-1: #e8e9ec;   /* 不纯白 */
--ink-2: #b3b5bb;
--ink-3: #83858c;
--ink-4: #63656b;

--accent:  #d97757;   /* 暗底提亮 + 降饱和 */
--success: #4ea97b;
--warning: #c2a544;
--error:   #e07a7a;
```

**挑战现有铁律**：项目当前规定"中性轴必须 R=G=B，禁任何蓝紫偏移"（`dark.css:7-8`）。
这条铁律是暗色"水泥感"的直接来源。建议**放宽为"色相允许，但饱和度上限 4%"**
——`#131417` 相对 `#131313` 只多了 2 个点的蓝，视觉上仍是中性，但暗底不再死黑。
如要保留铁律，至少把最暗一档从 `#0b0b0b` 提到 `#121212`（纯黑底下什么都读不出层）。

### 4.3 落地注意

- `scripts/check-theme-tokens.mjs` 有 CONTRACT 完整性校验：改名/删令牌需同步
  改校验器的清单，否则 CI 失败。建议**新增 4 个 surface 令牌（paper/desk/
  surface/overlay）+ 4 个 hairline/ink 令牌**，旧的 12 个 bg-* 保留一个版本做
  软别名，第二批再删。
- 主题仍按 `themes/<id>.css` 一套一取值表，registry 自动发现——新令牌天然支持
  rainforest / sunset，无需改架构。

## 5. 布局重构

### 5.1 外壳

1. **先修 CSS 双份 bug**：把 `components.css:18-180` 的 `.app-shell/.app-body/
   .pane/.titlebar/.pane-resizer` 整段删除，只保留 `components-layout.css`
   一份。恢复每主题的场景色。**这是让四套主题"活过来"的前提。**
2. **顶栏瘦身**：现 40px + 独立底色 + 底边框 → 视觉上又多一条横向分界。
   改为与侧栏同色（`--desk`），只在右侧窗口控制区保留分隔，靠留白分组，
   取消 `border-bottom`。
3. **侧栏**：去掉"每个区块一条分隔线"的现状，改为 **留白 + 字重**分组
   （`区块标题 11px / 字重 600 / 字距 0.04em / 上下间距 20px`）。
4. **主区**：`--paper` 铺满；左右案面（侧栏/右栏）比主区暗一档，主区自然"浮起来"，
   不需要任何边框。

### 5.2 圆角语法

现状 `4/6/8/10/12` 五档但全部挤在大容器上，导致"每个元素都圆"、重量均一。
新规则：**半径跟随尺寸反比**——小控件 6px，卡片 10px，大浮层 12px，
输入框/大面板 8px。同一屏内出现的圆角档位 ≤ 2。

## 6. 逐界面方案

### 6.1 对话页（核心战场）

#### 6.1.1 一"轮"的重新定义

现状把一轮拆成：思考卡 + 工具行 + 工具输出 + 审批卡 + 待办卡 + 正文 + 总结。
新结构是**一条时间轴 + 一段正文**：

```
│ ● 思考中 3.2s            ← 一行，>2s 才出现，可点开
│ ● read_file  src/main.rs ← 工具行（单行，等宽名 + 参数预览 + 状态点）
│ ● terminal   npm test    ← 运行中：状态点脉冲 + 右侧 3 行输出预览
│ ● ──────────────────────  ← 轮次分隔线（细，1px hairline，两端渐隐）
│   正文从这里流出：无气泡、无边框、无底色，
│   与纸面同底色，靠 68ch 行宽和段落节奏读。
│ ● todo  3 项  1/3        ← 收在正文末尾的一行链接，不打断阅读
```

#### 6.1.2 各类内容的呈现规则

| 内容 | 现状 | 建议 |
|---|---|---|
| 思考 | 独立卡片 | **默认完全隐藏**；流式中显示一行 `思考中 · 3.2s`（12px，ink-3），点击原地展开 |
| 工具调用 | 折叠卡片 + rail | 保留 rail 思路但**去掉容器边框**；名称用 mono 12px ink-2，参数预览 ink-4 单行省略；状态点 6px（成功=无点/成功=绿点/失败=红点/运行=呼吸） |
| 命令输出 | 深色终端面板 | 默认显示**最后 3 行**，可展开为终端（等宽 13px，`--ink-1` on `#101114` 深底，与纸面形成"案"对比）；加"复制/全屏"两个 icon（hover 显形） |
| 审批 | 玻璃卡片 | 改为**墨点睛**：整卡用 `--accent-soft` 4% 底 + 左侧 2px accent 竖条，标题"需要你的决定"，主体是动作+影响面一句话，底部两个按钮（右=实心 accent，左=ghost） |
| 用户消息 | 气泡+边框 | **去边框**，改 `--surface` 底 + `--hairline` 极轻描边（0.5px 视觉）；圆角只削左下角（现状已对） |
| 正文 | 有卡片语言 | 纯纸面，见 6.1.3 |
| 轮次总结/compaction | 大卡片 | 变成一条**渐隐分隔线 + 一行 chip**：`已压缩 12 条历史 · 查看` |
| 待办 | 卡片 | 左侧 2px 竖条 + 紧凑行；完成态用**删除线 + ink-4**，不用绿色对勾块 |
| 子 agent | ? | 折叠为时间轴上一行 `sub-agent · 代码审查 · 完成`，点开看摘要 |

#### 6.1.3 LLM 输出的排版细则（抄墨水屏）

这是"久看不累"最直接见效的地方：

```css
.paper {                       /* 纸面容器 */
  max-width: 68ch;             /* 中文约 34 字/行，长行不折返 */
  font-size: 14px;
  line-height: 1.75;           /* 比现在 1.68 再松一点 */
  color: var(--ink-1);
}
.paper p      { margin: 0 0 0.75em; }
.paper h1,h2,h3 {
  /* 不用大字号做层级——小标题 + 大间距更像书 */
  font-size: 14px; font-weight: 600; letter-spacing: 0.01em;
  margin: 1.6em 0 0.6em; color: var(--ink-1);
}
.paper h3     { font-size: 13px; color: var(--ink-2); }
.paper ul li  { margin: 0.2em 0; }
.paper ul li::marker { color: var(--ink-4); }   /* 符号去色，不抢注意 */
.paper a      { color: var(--ink-1); border-bottom: 1px solid var(--accent); }
.paper blockquote {           /* 引用不用灰底块，用一条竖线 */
  border-left: 2px solid var(--hairline-firm);
  padding-left: 14px; color: var(--ink-2);
}
.paper code   {               /* 行内代码不用底色块 */
  font-family: var(--font-mono); font-size: 0.92em;
  color: var(--ink-1);
  background: none;           /* 现为浅底块 → 改为仅靠字族区分 */
}
.paper pre    {               /* 代码块保留"案"感 */
  background: var(--desk); border: 1px solid var(--hairline);
  border-radius: 8px; padding: 12px 14px;
  font-size: 13px; line-height: 1.6;
}
.paper table  { /* 细线表，无斑马纹无外框重线 */ }
.paper hr     { border: 0; height: 1px; background: linear-gradient(90deg,
                transparent, var(--hairline-firm) 20%, var(--hairline-firm) 80%, transparent); }
```

**中文专属**：正文 `text-wrap: pretty`；`line-break: strict`；中英混排在
mono 上下文里加 `font-variant-numeric: tabular-nums`。

### 6.2 工作台：可移动的悬浮对话（用户方案 + 增强）

用户的想法是对的，并且可以再进一步——**不要只做"悬浮对话窗"，做"智能体在场指示器"**。

#### 6.2.1 为什么这个方向是对的

现状工作台是"左画布 + 右 460px 固定栏"（`workbench.css:109-120`），画布被永久
切掉三分之一，且切页就没了。把对话收成悬浮体后：

- 画布拿到 100% 宽度（工作台本身是画布工具，最需要面积）
- 对话变成**按需的第二注意力**，不与画布争夺常驻空间
- 更进一步：球可以**跨页面常驻**——你在设置页改配置时，也能一眼看到"agent 在想/
  在等你批准"。这是当前所有 agent 产品的共同盲区（切页即失去对 agent 的感知）。

#### 6.2.2 形态规格

**收起态（球）**

| 属性 | 规格 |
|---|---|
| 尺寸 | 48px 圆形，`--surface` 底 + `--shadow-pop` + `1px --hairline` |
| 默认位置 | 右下角，距右 24px / 距下 24px |
| 拖拽 | 任意位置；拖动时显示到边吸附预览（4px 虚线），松手落位 |
| 位置记忆 | `localStorage` 存**视口比例**（x/innerWidth）而非绝对像素，换显示器不跑偏 |
| 层级 | `position: fixed; z-index: 40`（低于弹窗 60、高于页面内容） |

**状态环（R5 的直接落地——球是全屏唯一"最亮/最饱和"的东西）**

| Agent 状态 | 环的表现 |
|---|---|
| 空闲 | 无环，球静止 |
| 思考中 | 外环 1.5px **缓慢旋转的虚线弧**（`--ink-4`，8s/圈，不刺眼） |
| 工具执行中 | 外环**不确定态脉冲**（呼吸 opacity 0.3↔0.8，1.6s） |
| **待你审批** | 外环变 `--warning`，做**一次** 1.2s 呼吸后转常亮（一次性，不持续骚扰） |
| 刚完成 | 对勾沿路径划过一次（300ms），然后回到空闲 |
| 有新消息 | 右上角 8px `--accent` 圆点，点击即展开并清除 |

**展开态（窗）**

| 属性 | 规格 |
|---|---|
| 尺寸 | 宽 `clamp(360px, 30vw, 480px)`，高 `clamp(320px, 60vh, 640px)` |
| 展开动画 | 从**球的实际坐标**做 `transform: scale(.92) translate(...)` + opacity，180ms `--ease-out`；`transform-origin` 按球在球的哪一侧计算 |
| 移动 | 顶栏（36px）拖动；标题栏显示会话名 + 状态 + 收起/固定按钮 |
| 缩放 | 右下角 12px 命中区拖拽调整 |
| 内容 | 完整 ChatView（消息 + 输入框），复用现有组件，不重写 |
| 收起 | Esc / 关闭按钮 / 点击球 / **离开工作台自动收起**（保留球的位置记忆） |
| 窄窗降级 | < 900px：球吸附右下角不可拖动；展开态全屏 sheet |

#### 6.2.3 交互细节（决定"人性化"成败）

- **滚入时不抢焦点**：展开后不自动 focus 输入框（用户可能在看画布），
  首次点击球时才 focus。
- **Esc 优先级**：先关浮窗内的展开面板（如工具输出），再关浮窗，再关全局弹窗。
- **快捷键**：`Ctrl+Shift+C` 在任意页面唤起/收起（用 `preventDefault` 避免与
  Chrome 冲突）。
- **不遮挡**：球默认右下，但右栏/产物面板打开时自动让位 8px；用户手动拖过则
  尊重用户位置不再自动让。
- **流式降频**：窗内沿用上一轮做的 Markdown 120ms 节流 + ResizeObserver 跟随，
  避免悬浮窗开着时拖动画布掉帧。

### 6.3 产物预览（ArtifactPreviewModal）

现状：全屏 modal + `backdrop-filter: blur(4px)` + 遮罩 —— 又一层盒子。
建议：改为**右侧滑入的浮层面板**（宽 46%，最大 720px，`--overlay` 底 + 阴影，
无遮罩，可与主区同时交互），ESC/关闭按钮/再次点击图标收起。文件预览的
"打开"从"全屏打断"变成"侧旁查看"，是工作流质变。

## 8. 明确不做的事

- **不做**多主题大改版：rainforest / sunset 保持，只在新令牌下微调饱和度。
  主题多不等于好看，先把两套主色做好。
- **不做**毛玻璃：玻璃是 2021 年的语言，且与"墨水屏克制"背道而驰，还吃 GPU
  （见上一轮性能分析）。`--glass-*` 令牌建议保留但只在真正需要"浮在图像上"
  的场景使用，默认不启用。
- **不做**深色模式下的纯黑 OLED 主题：省电收益对桌面应用可忽略，代价是层次全无。
- **不引入**新的 CSS 方案（Tailwind utility 已足够），本次只改令牌与语义。
