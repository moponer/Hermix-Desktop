# 协作空间 UI 重设计方案

**版本**: v1.0
**日期**: 2026-07-28
**状态**: 待评审
**目标模块**: 协作空间（房间列表 + 对话区）

---

## 一、现状诊断

### 1.1 核心问题（按严重度排序）

| 序号 | 问题 | 影响 |
|---|---|---|
| P0 | 产品概念混乱：群聊/房间/项目/聊天室/团队同时出现，用户无法建立稳定心智 | 信息架构崩塌 |
| P0 | 同一状态被重复表达 5~6 次（暂无成员、总管等待等） | 视觉噪声 |
| P0 | 输入框与对话区宽度不一致、颜色脱节，像两张皮 | 组件割裂 |
| P1 | 顶部元素平铺：任务/规则/成员管理/青铜/皇冠全部同权重 | 缺乏主次 |
| P1 | 左侧列表无层次：选中/未选中只能靠边框细线区分 | 导航迷失 |
| P1 | 颜色无体系：蓝/橙/黄/米/灰五种颜色各说各话 | 视觉碎片 |
| P2 | "青铜"徽章含义不明，且全屏重复 | 装饰噪声 |
| P2 | "点击右侧添加描述"等方位式文案 | 引导失效 |

### 1.2 根本原因

不是排版问题，而是**信息架构 + 视觉层级 + 组件一致性**三个维度同时失控。

## 二、设计原则

### 2.1 三档信息层级

只用三档字号 + 三档字重 + 一档主色构建层次：

| 层级 | 用途 | 字号 | 字重 | 颜色 token |
|---|---|---|---|---|
| H1 | 房间名称、核心状态标题 | 18px | 600 | `--text-primary` |
| H2 | 副信息（成员数、最后消息） | 12px | 400 | `--text-secondary` |
| Body | 正文描述 | 14px | 400 | `--text-primary` |
| Caption | 输入框 placeholder、辅助文字 | 13px | 400 | `--text-tertiary` |

**禁用**：`font-size: 15px`、`font-size: 13px` 等中间档位。

### 2.2 颜色体系

| 类别 | Token | 用途 | 出现频率 |
|---|---|---|---|
| 中性 | `--text-primary` `#1F2328` | 标题、正文 | 高 |
| 中性 | `--text-secondary` `#4E5969` | 副信息 | 高 |
| 中性 | `--text-tertiary` `#86909C` | 弱化文字、placeholder | 高 |
| 中性 | `--bg-canvas` `#F7F8FA` | 页面底色 | 高 |
| 中性 | `--bg-surface` `#FFFFFF` | 卡片/容器底色 | 高 |
| 中性 | `--border-subtle` `#F2F3F5` | 分割线、禁用边框 | 高 |
| 中性 | `--border-default` `#C9CDD4` | 输入框默认描边 | 中 |
| 主色 | `--brand-primary` `#165DFF` | **仅用于主操作按钮 + 选中态强调条** | 低 |
| 主色 | `--brand-primary-hover` `#0E42D2` | 主按钮悬停 | 低 |
| 主色 | `--brand-primary-bg` `#F2F7FF` | 选中项背景 | 低 |
| 状态 | `--success` `#00B42A` | 在线状态 | 低 |
| 状态 | `--warning` `#FF7D00` | 警告、提示 | 低 |
| 状态 | `--error` `#F53F3F` | 错误、禁用 | 低 |

**禁用**：橙色等级徽章、黄色皇冠、米色背景块、紫色装饰色。

### 2.3 间距系统

只用 4 的倍数：

```
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
```

| 场景 | 间距 |
|---|---|
| 列表项内文字行距 | 4px |
| 卡片内元素间距 | 12px |
| 卡片内边距 | 16px / 20px |
| 区块之间 | 24px / 32px |
| 页面左右留白 | 24px |

## 四、左侧房间列表

### 4.1 结构

```
┌─────────────────────────┐
│  协作空间            ＋ │  ← 顶部标题栏,高度 56px
├─────────────────────────┤
│                         │
│  ▌333                   │  ← 选中项:左侧4px主蓝条 + #F2F7FF 底
│    还没有消息           │
│                         │
│    ddda2                │  ← 未选中:无侧条、透明底
│    Hermix:完成 · 3      │
│                         │
│    ddd                  │
│    暂无成员             │
│                         │
└─────────────────────────┘
```

### 4.2 房间项样式

**容器**：
- 高度 56px
- 水平内边距 16px
- 垂直内边距 8px
- 圆角 8px（与外层卡片区分）
- 内边距至侧栏边缘 8px（避免贴边）

**标题（房间名）**：
- 字号 14px
- 字重 600
- 颜色 `--text-primary`
- 单行截断省略号

**副标题（最后消息/状态）**：
- 字号 12px
- 字重 400
- 颜色 `--text-tertiary`
- 单行截断省略号

**选中态**：
- 背景 `--brand-primary-bg` `#F2F7FF`
- 左侧 4px 主蓝竖条（绝对定位或 border-left）
- 圆角 8px

**未选中态**：
- 背景透明
- 无侧条

**悬停态**（未选中时）：
- 背景 `--bg-canvas` `#F7F8FA`

**未读/成员徽章**（右上）：
- 字号 10px
- 字重 500
- 颜色 `--text-tertiary`
- 无背景或纯灰背景
- 仅在有数据时显示

### 4.3 新建按钮

- 位置：侧栏顶部右侧
- 字号 18px
- 字重 400
- 颜色 `--brand-primary`
- 不使用圆角图标块，直接用 `＋` 字符
- hover 时背景 `--bg-canvas`

### 4.4 测试房间差异化处理

为了让三个测试房间（333 / ddda2 / ddd）有视觉区分，必须填充差异化数据：

| 房间 | 标题 | 副标题 | 徽章 |
|---|---|---|---|
| 333（选中） | 333 | 还没有消息 | — |
| ddda2 | ddda2 | Hermix：需求分析已完成 | 3 |
| ddd | ddd | 暂无成员 | — |

## 五、主区（房间详情）

### 5.1 容器结构

整个主区是一个**单一卡片容器**：

```css
.main-room {
  background: var(--bg-surface);
  border: 1px solid var(--border-subtle);
  border-radius: 12px;
  display: flex;
  flex-direction: column;
  height: 100%;
  overflow: hidden;
}
```

**包含三块**（自上而下）：
1. 顶部信息区（高度自适应，约 64px）
2. 对话区（flex: 1）
3. 输入区（高度 48px + 上下内边距）

三块之间用 **1px `--border-subtle` 分割线**分隔，不另加边框。

### 5.2 顶部信息区

```
┌────────────────────────────────────────────────────────┐
│  ▌333                                          ···  │
│   3 名成员 · 在线                                       │
└────────────────────────────────────────────────────────┘
```

**房间名**：
- 字号 18px
- 字重 600
- 颜色 `--text-primary`
- 左侧 4px 主蓝竖条（与选中态呼应，标识当前房间）

**副信息**：
- 字号 12px
- 字重 400
- 颜色 `--text-secondary`
- 格式：`{成员数} 名成员 · {在线状态}`

**更多操作 `···`**：
- 顶部右侧
- 字号 16px
- 颜色 `--text-tertiary`
- hover 背景 `--bg-canvas`，圆角 4px
- 点击展开下拉：编辑名称、编辑描述、查看成员、删除房间

**描述区域**（可选）：
- 若有描述：在副信息下方一行，12px，弱化色
- 若无描述：内联按钮 `+ 添加描述`，12px，主色

**删除项**：
- ~~任务按钮~~ → 移入 `···` 菜单
- ~~规则按钮~~ → 移入 `···` 菜单
- ~~青铜 ×1~~ → 删除
- ~~皇冠~~ → 删除
- ~~编辑铅笔（独立悬浮）~~ → 移入 `···` 菜单

### 5.3 对话区（空状态）

空状态下居中显示三段式：

```
              ✦                              ← 24px 主蓝线性图标
        还没有协作成员                        ← 16px / 600 / --text-primary
  邀请成员加入后即可开始协作                   ← 13px / 400 / --text-secondary
        ┌──────────┐
        │ 邀请成员 │                          ← 唯一主按钮,主蓝实心
        └──────────┘
```

**布局规则**：
- 垂直水平居中（flex）
- 图标 + 标题 + 描述 + 按钮 四段，间距固定 8 / 12 / 16
- 图标颜色 `--brand-primary`，线宽 1.5px
- 按钮高度 36px，水平内边距 20px

**删除项**：
- ~~米色背景框~~ → 删除
- ~~管家状态卡~~ → 删除（合并到主按钮）
- ~~多处"等待成员"提示~~ → 只保留此处一处

### 5.4 输入区

**正常态（有成员）**：

```
┌────────────────────────────────────────────────────────┐
│  给总管发送消息……                       📎  🎤  ➤    │
└────────────────────────────────────────────────────────┘
```

- 容器背景 = 主区卡片背景（**与对话区共用同一底色**）
- 顶部 1px `--border-subtle` 分割线（**不另加边框**）
- 左右内边距严格对齐对话区（16px 或 20px）
- 输入框本身无背景、无边框，文字直接落在卡片底色上
- placeholder 颜色 `--text-tertiary`
- 右侧图标按钮 32×32，间距 4px，颜色 `--text-tertiary`
- 发送按钮：主色 `#165DFF`，禁用时 `#C9CDD4`

**禁用态（无成员）**：

- 输入框整体置灰（透明度 0.5）
- placeholder 改为 `添加成员后可发送消息`
- 所有图标禁用态颜色 `--text-tertiary`
- 发送按钮禁用色 `#C9CDD4`
- **不保留半吊子的"灰色描边 + 蓝色图标"组合**

## 六、组件规范

### 6.1 按钮

| 类型 | 样式 | 用途 |
|---|---|---|
| 主按钮 | bg `--brand-primary`, color `#FFF`, height 36px, radius 8px, px 20px | 邀请成员、确认操作 |
| 次按钮 | bg transparent, color `--text-primary`, border 1px `--border-default`, height 36px, radius 8px, px 20px | 取消、辅助操作 |
| 文本按钮 | bg transparent, color `--brand-primary`, height 32px, px 8px | `+ 添加描述`、链接式操作 |
| 图标按钮 | bg transparent, color `--text-tertiary`, size 32×32, radius 4px | 工具栏、更多操作 |

### 6.2 头像占位

- 尺寸 32×32（列表）/ 24×24（小头像）
- 圆角 50%
- 背景色循环使用 `--brand-primary` / `#00B42A` / `#FF7D00` / `#722ED1`
- 文字居中，12px / 14px，白色

### 6.3 空状态图标

- 容器 64×64，背景透明
- 图标 24×24，线条 1.5px
- 颜色 `--brand-primary`
- 线型图标库（lucide / heroicons），不用 emoji

## 八、产品文案统一

### 8.1 名词表（强制统一）

| 弃用 | 统一为 |
|---|---|
| 群聊 / 聊天室 / 房间 / 项目 / 团队 | **房间**（协作空间内的基本单位） |
| 项目总管 | **总管**（房间内的 AI 协调者） |
| 成员管理 | **成员**（侧栏常驻入口） |
| 添加成员 | **邀请成员**（空状态主操作） |

### 8.2 文案规则

- **不用方位词**："点击右侧"、"上方"、"下面" → 改为具体组件名
- **不用"暂无 + 名词"重复三次**：选一处明确位置展示，其他位置用 Tab 或图标替代
- **按钮文案用动词**：`邀请成员`、`发送`、`保存`（不要用 `确定`、`好的`）
- **状态文案要可执行**：`还没有协作成员` + `邀请成员加入后即可开始协作` + `邀请成员`（按钮）

## 九、实施优先级

### P0：信息架构 + 组件一致性（必须先做）

1. 统一名词：房间 / 总管 / 成员 / 邀请成员
2. 输入框融入主区容器，共用底色和边距
3. 删除重复的"暂无成员"提示，只留一处
4. 删除"青铜"、"皇冠"、"任务"、"规则"独立按钮
5. 空状态居中，标准化三段式

### P1：视觉层级重构

6. 顶部信息区压缩到两行：房间名 + 副信息
7. 侧栏选中态用 4px 主蓝侧条 + 浅蓝底
8. 颜色体系收敛到三类（中性 / 主蓝 / 状态）
9. 三档字号 + 三档字重确立
10. 间距系统统一为 4 的倍数

### P2：细节完善

11. 侧栏项填充差异化数据（最后消息、时间、成员数）
12. 输入框禁用态正确实现（整体置灰，不留半吊子样式）
13. `···` 菜单收纳所有次要操作
14. 文案去方位词，统一为动词

## 十、验收标准

### 10.1 视觉验收

- [ ] 三秒内能识别出"我在哪个房间"和"下一步该做什么"
- [ ] 侧栏选中态一眼可见，不依赖边框
- [ ] 输入框与对话区视觉上是一个整体（同一容器、同一圆角、同一描边、同一左右边距）
- [ ] 空状态在对话区真正居中
- [ ] 全屏找不到第二种橙色 / 黄色装饰

### 10.2 信息架构验收

- [ ] 全屏"还没有成员"类提示只出现一次
- [ ] "邀请成员"是空状态下唯一的主操作
- [ ] 顶部不再有任务 / 规则 / 成员管理独立按钮
- [ ] 所有次要操作都收进 `···` 菜单

### 10.3 组件一致性验收

- [ ] 输入框、对话区、顶部区共用同一个卡片容器
- [ ] 所有按钮只有四种类型（主 / 次 / 文本 / 图标）
- [ ] 所有图标来自同一图标库，统一线条粗细
- [ ] 所有间距是 4 的倍数
