# Decision Notes（决策笔记）

本目录是 hermix 的唯一决策记录地。一类文件住在这里：**Decision Note** ——
记录影响本代码库的一个决策或提案：*为什么这么做、放弃了什么、哪些方案被击败*。
这些是代码和普通文档装不下的内容。

制度抄自 deepseek-ai/deepseek-harness 的 Agent Notes（见
`docs/notes/archived/process/deepseek-harness 借鉴笔记（已删除，见 git 历史）.md`），按本项目规模裁剪。

## 目录结构与命名

每篇笔记有两个轴，都编码在**路径**里：`{lifecycle}/{class}/yyyy-mm-dd-topic.md`

- **Lifecycle**（顶层目录）= 笔记状态，状态变化时文件在目录间移动：
  - `proposed/` — 已评审、未实施（或只部分实施）的提案
  - `implemented/` — 决策已落地。文件记录"决定了什么、否决了什么"，
    并**与实际交付保持同步**：后续改动移动了文件、改了名、换了默认值时，
    同一提交里更新笔记中的事实（只改事实——路径、名称、结构——不改决策本身）
  - `rejected/` — 提案被考虑后否决。只要它的论证还能防止一个诱人的错误就保留；
    防止不了了就连同中英副本一起删
- **Class**（嵌套目录）= 决策种类，闭集：
  - `feature` — 新的用户/模型可见能力
  - `bug-fix` — 修复缺陷或补上复盘暴露的缺口
  - `simplification` — 删除代码、行为或表面积，不新增能力
  - `architecture` — 对**已交付源码**的结构性决策：crate 之间如何关联、运行时词汇
  - `process` — **围绕**代码的工具、策略、流程：CI 门禁、脚本、工作流
  - `testing` — 测试基建与策略

文件名日期 = 主题**首次提出**的日期（以 git 历史为准）。笔记间互引用
相对 markdown 链接，不用裸文字或编号——可机械检查、可跨目录移动后不失效。

**禁止生成 INDEX.md**：目录树 + 仓库搜索就是清单。生成式索引是必然的
合并冲突点（每个分支动一篇都要重写同一文件）。

## 文件格式

每篇笔记头三行固定：

```markdown
# Decision Note: <标题>

Status: proposed|implemented|rejected — 一句话现状
```

正文必须含以下节：

- **## Decision** — 决定了什么（implemented 用现在时描述已交付的现实，
  禁止 "should" 式提案语气）
- **## Alternatives considered** — 考虑过哪些方案、为何否决。
  **没有记录被击败方案的决策会招致重新争论**——这节是强制的
- **## Consequences** — 代价/放弃了什么（What we give up）

simplification 类笔记还必须含 **## Reintroduction conditions** —
什么证据出现时该功能应该回来。这防止"删了不敢回"和"悄悄加回"两个方向。

## 何时写一篇

同一次 PR 中，只有当代码、测试和现有文档都解释不了的**持久决策依据**
出现时才写。大型未来工作的提案从 `proposed/` 开始；已拍板的决策直接进
`implemented/`。机械性/局部改动（含局部 UI 调整）豁免。

- 更新已有笔记以满足规则优于新建重复笔记
- 笔记绝不被编辑成**另一个决策**：被取代时写新笔记，两者互链；
  旧笔记随后按合并规则处理
- **写新笔记时当场检查是否取代旧笔记**，是则在同一 PR 里归档旧笔记——
  替代决策的作者掌握最新证据，不得推迟到"以后清理"

## 归档与删除

- 只描述小 UI 调整或纯机械改动的 implemented 笔记 → 直接删除
- 决策已交付完毕、依据不太可能再指导未来工作、但仍有历史决策价值的
  → 移入 `archived/{class}/`，在 Status 行下加 `Archived: YYYY-MM-DD` 行
- **归档件永久冻结**：不编辑、不重排版、不当作现行行为的依据
- proposed 笔记永远不归档：过时就转为 rejected
