# Decision Note: 阿黎的角色动画系统 —— 多视图设定 → 预制动作 → 按状态编排

Status: proposed — 调研完成，技术路线待拍板，未实施。

## Decision

把阿黎从「会变表情的图标」升级成「有姿态的角色」，分四层建设：

1. **角色设定层**：三视图（正/侧/背）+ 表情集 + 部件拆分，定比例、色板、轮廓特征；
2. **动作资产层**：每个动作 = 一段预制的帧序列（或骨骼关键帧），12fps 起，不追求 60fps；
3. **动作元数据层**：每个动作带 `条件 / 权重 / 时长 / 冷却 / 帧序列 / 可衔接动作`；
4. **编排层（Director）**：纯逻辑、可重放 —— 输入状态与心情，输出「现在播哪个动作」，并处理打断、排队、去重。

**推荐技术路线：手绘/导出图集帧 + Canvas 2D + 自研 Director（方案 A），Rive 作为技术允许时的升级项（方案 B）。**

理由：这条路与已被验证的两个参考实现同构（DSH 大肥鱼、Shimeji），零运行时依赖，美术格式通用（PNG 图集），角色包可热替换；而 Rive 虽然运行体积极小、状态机内建，但要求美术在 Rive 编辑器里重做资产，且 .riv 是二进制、跨版本兼容与外部角色包分发都更受约束。

## 现状为什么不行（先把问题定义清楚）

现行 `components/twin/AliCharacter.tsx` 是**一个 SVG、五套眼睛**：身体形状恒定，只换眼睛与一个小标记。

对比参考实现的规模就能看出差距：

| | 动作数 | 姿态（帧）数 | 表达手段 |
|---|---|---|---|
| 现行阿黎 | 5 个状态 | 约 5 个（同身体换眼） | SVG 路径切换 |
| DSH 大肥鱼 | 101 类动作（29 原有 + 72 新增） | **432 个新绘制姿态**、13 种举牌小剧场 | 6 张透明图集 + 程序关键帧 + 场景道具，合成到 Canvas 2D |
| Shimeji（经典桌宠） | 数十个动作 | 每动作 2–8 帧 | PNG 序列 + 声明式 XML |

**结论：角色感 = 姿态数量 × 姿态差异度。** 只换眼睛不换身体，永远是图标。这是设计问题，不是渲染问题。

## 参考实现的确切机制

### DSH 大肥鱼（`gosomea/dsh-bigfish`，据 `docs/architecture.md`）

- **角色包**：带 manifest 的受限归档（`.dshpet`），contract 校验 → Host 侧带 revision 的**整批原子写入** + 跨进程心跳锁 → 浏览器侧引用计数加载/释放。
- **三轨合成**：① 图集连续帧（sprite sheet + 坐标 JSON，内置六张透明图集，随包内嵌、无 CDN）；② **程序关键帧**（代码插值生成，非位图）；③ **场景道具**（布景 + 次级位移 `motion-transform.ts`）。
- **不是骨骼动画**：文档里没有 pose list / skeleton 概念，也没有 loop / priority 字段。
- **动作元数据六类**：`条件`、`权重`、`时长`、`冷却`、`帧序列`、`场景状态`。
- **决策位置**：`src/domain/` 的 **Director** —— 纯逻辑、**可重放**（同一事件序列复现同一动作序列），另有 `pet/` 的通用动作调度。宿主**不参与**决策，插件只订阅公开事件流。
- **状态映射**：只有 `turn/end` + completed 触发庆祝；`settle-assistant`（单次请求结束）不算。遥测按 5 Hz 出数值快照，动画 30 FPS，DPR 上限 2，隐藏标签页暂停绘制。

### Shimeji（`actions.xml` + `behaviors.xml`）

- `actions.xml` 定义**动作本身**：由哪几张图、以多快的帧时序、锚点在哪组成，支持条件动画选择。
- `behaviors.xml` 定义**行为逻辑**：什么情况下执行哪个动作、频率 `Frequency` 多大。
- 两个文件都是**声明式 XML，纯文本可改** —— 不写代码就能调角色性格与活跃度。这正是「预制动作 + 数据驱动编排」的原始形态。

### Rive（对照项）

- 运行体积：Web Canvas **Lite** 222 KB（压缩）/ 707 KB（未压缩）；Web Canvas 567 KB / 1728 KB；WebGL2 648 KB / 2179 KB。
- 能力：2D 矢量绑定 + **状态机内建在 .riv 里** + Data Binding（动画属性可直接绑实时数值）+ React 集成 `@rive-app/react-canvas`（`useRive`）。
- 代价：资产必须在 Rive 编辑器里重做；`.riv` 为二进制；外部角色包分发与版本兼容更受约束；编辑器的功能分档需要确认授权。

## 四条路线对比

| | A. 图集帧 + 自研 Director | B. Rive | C. Live2D | D. 3D（glTF） |
|---|---|---|---|---|
| 运行时成本 | 0（Canvas 2D 原生） | +222 KB（lite） | 重（SDK + 模型） | 重（引擎 + 模型） |
| 角色感上限 | 高（取决于画的帧数） | 高（骨骼 + 网格变形） | 高（尤其脸部） | 最高 |
| 换装/换色 | 要重画 | 强（骨骼 + 换附件） | 中 | 强 |
| 外部角色包 | 易（PNG + JSON，透明可审） | 中（二进制、需编辑器） | 难 | 难 |
| 美术门槛 | 会画就能做 | 要学 Rive | 要学 Cubism | 要建模绑骨 |
| 与参考实现同构 | 是（大肥鱼 / Shimeji） | 否 | 否 | 否 |
| 适合本项目 | **是** | 二期可选 | 否（偏脸部） | 否（成本远超收益） |

Live2D 排除的理由：它擅长的是**脸部参数与实时表演**（VTuber），全身动作编排不是它的强项，且包体与授权都重。3D 排除的理由：桌面 48px 的尺寸用不上三维信息，建模绑骨成本是二维的数倍。

## 推荐架构：四层

```text
① 设定  character/sheet.png      三视图 + 表情集 + 色板（人看的，不进运行时）
        ↓ 拆部件/画动作
② 资产  character/atlas.png      图集（PNG）+ atlas.json（每帧坐标/锚点）
        character/actions.json   动作元数据
        ↓
③ 元数据 action = {
            id, frames[], fps, loop,
            anchor, layer,               // 锚点决定"脚踩在哪"，层级决定遮挡
            weight, cooldownMs,          // 竞争与去重
            when: { moods[], states[] }, // 何时可播
            next: [actionId]             // 可衔接动作（序列编排的边）
          }
        ↓
④ 编排  Director（纯函数、可重放）
        输入：TwinState { phase, activeRuns, pendingApprovals, watchFailed, mood }
        输出：PlaybackCommand { actionId, startFrame, interrupt }
```

Director 的规则（照抄参考实现里被验证过的部分，补上我们需要的优先级）：

1. **候选筛选**：`when` 匹配当前状态的候选集；
2. **加权随机**：按 `weight × moodBoost(action, mood)` 抽一个（避免每次都同一动作）；
3. **冷却去重**：`cooldownMs` 内不重播；同一动作连续两次的权重减半；
4. **打断规则**：`alert` 类动作可打断一切（异常要立刻被看见）；`idle → work` 允许打断；`celebrate` 不可被打断（演完再走）；
5. **排队**：不可打断的动作进队列，最多 1 个（不堆演出）；
6. **可重放**：同一事件序列必须复现同一动作序列 —— 把随机数种子作为输入的一部分，否则没法测。

## 三视图 → 动作：具体流程

用户说的「画三视图，最后合成动作」，在二维里是一条确定的生产线：

1. **三视图定标准**：正/侧/背，确定头身比、色板（≤6 色 + 1 强调）、轮廓剪影特征（48px 下能认出是谁的唯一依据）；
2. **表情集**：眼/眉/嘴做成可替换层（同一身体 × 8 表情 = 8 个情绪，成本极低、收益最高 —— 这是现行 SVG 唯一做对的地方，要保留）；
3. **动作帧**：每个动作 3–8 帧，12 fps。**关键在关键姿态而不是帧数**：起步夸张、落地有重量、呼吸有起伏；
4. **次级运动**：头发/衣角/尾巴/耳机线延迟 2–3 帧跟随（大肥鱼的 `motion-transform` 就是干这个的，纯代码插值，不额外画帧）；
5. **导出**：PNG 序列 → 图集打包 → `atlas.json`（坐标 + 锚点）；
6. **标注**：填 `actions.json` 的六类元数据；
7. **验收**：在 48px 与 160px 两个尺寸下看 —— 小尺寸认得出，大尺寸不糊。

**一条重要边界**：三视图本身不"合成"动作。它是角色的设计基准；动作仍然是逐帧画（或用骨骼工具绑定后导出）。所谓"从一张图自动生成帧序列"的工具确实存在（例如 `zhizhiji-shimeji` 号称用一张静态卡通图生成桌宠帧序列），但产出质量需要人工筛帧与修形，适合当**产能放大器**，不能当生产线的全部。

## 「按心情自己编排动作」怎么实现

这里的"自己编排"不是生成新动画，而是**从预制动作池里按当前状态与心情组合出序列**。三件事：

**① 心情 = 几个可观测标量，不是玄学**

| 变量 | 来源（页面上已有） | 影响 |
|---|---|---|
| `alertness` | 挂起审批数、守望任务 `failed` 数 | 提高警觉类动作权重、加快呼吸节奏 |
| `activity` | 在跑任务数、最近 5 分钟有无新消息 | 工作类动作 vs 待机类动作 |
| `fatigue` | 今日 token 花费 / 连续运行时长 | 高疲劳时插入打哈欠、趴下、发呆 |
| `warmth` | 用户最近是否与她说话、是否批准了她的请求 | 亲近类动作（靠近、举牌、晃尾巴） |

四个标量各取 0–1，由**纯函数**从现有 `TwinState` 算出 —— 不新增后端字段，全部可从已接通的接口推导。

**② 序列编排 = 动作图上的短路径**

`next: [actionId]` 就是图的边。Director 选完动作后，若该动作有 `next` 且时长 < 阈值，可以连播 2–3 个形成"小剧场"（大肥鱼的 13 种举牌小剧场就是这种短序列）。规则：**最多连 3 个、总时长 ≤ 6 秒、结束时必须回到 idle 或 work**——否则会变成让人分心的循环演出。

**③ 台词与动作解耦**

台词不进动作帧，单独一层（气泡），由同一 Director 输出 `{ actionId, lineId }`。理由：台词要随状态变化（"还有 2 件等你拍板"），画进帧里就死了。

## 落地约束（必须遵守，否则会被门禁或体验反噬）

| 约束 | 原因 | 做法 |
|---|---|---|
| **动作必须绑定状态** | 设计门禁把"装饰性动画"判为假活力（此前脉冲点与扫描带都被拦下） | 每个动作在 `when` 里都有对应状态；`idle` 的合法性来自"在场感"，需在描述里写清 |
| **不做无限循环演出** | 同上，且会抢注意力 | 序列 ≤ 3 个动作、≤ 6 秒，必须回落 |
| **30 FPS 上限、DPR ≤ 2** | 抄大肥鱼实测值；WebView2 上省电 | 帧时序按 12 fps 设计，渲染上限 30 |
| **隐藏/失焦暂停** | 桌面端长期挂着 | `document.visibilityState` 驱动暂停 |
| **reduced-motion 降级** | 无障碍 | 直接定格到目标动作的首帧（表情仍在，动作不动） |
| **包体积预算** | 已有 dsh 引擎等大件 | 12 个动作 × 4 帧 @2x ≈ 1–2 MB；超过 5 MB 就改为首次下载（已有先例） |

## 分期

| 期 | 内容 | 验收 |
|---|---|---|
| P0 | 角色设定（三视图 + 表情集 + 色板）+ 8 个动作（idle / think / work / happy / alert / sleep / wave / tilt）+ 图集渲染器 | 48px 与 160px 都能认出是同一个人；8 个动作肉眼可区分 |
| P1 | `actions.json` 六类元数据 + Director（筛选/加权/冷却/打断/队列/可重放） | 同一状态序列回放结果一致；alert 必定打断 idle |
| P2 | 表情层与台词气泡解耦 | 同一动作配不同表情与台词不重画 |
| P3 | 心情四标量 + 序列图（≤3 连播） | 疲劳高时出现打哈欠；有审批时警觉姿态优先 |
| P4 | 角色包可替换（manifest 校验 + 版本 + 热替换） | 换一个角色包不改代码 |

## Alternatives considered

1. **继续用 SVG 路径动画** — 否决。只换眼睛不换身体，做不出重量与次级运动；姿态数量是角色感的来源，SVG 手写路径的生产成本比画帧更高。
2. **直接上 Rive** — 不作为首选。运行体积确实极小、状态机内建很贴合，但要求美术在 Rive 里重做资产，且 `.riv` 二进制不利于"角色包可被用户替换/审阅"。保留为技术升级项：`actions.json` 与 Rive 状态机的输入形态可以对齐，届时只需换渲染层。
3. **Live2D** — 否决。强项是脸部实时表演，全身动作编排不是它的场景；授权与包体都重。
4. **3D（三视图建模 + glTF）** — 否决。桌面 48px 用不上三维信息，建模绑骨成本是二维数倍。
5. **纯程序化动画（代码插值出一切）** — 否决。参考实现里程序关键帧只用于次级位移与呼吸，主体动作仍是画出来的。全靠代码插值的结果是"抽搐的几何体"。
6. **让 LLM 实时生成动作序列** — 否决。延迟不可接受、结果不可重放、无法测试。LLM 可以参与"写好 actions.json 的初稿"，但不进运行时。

## Consequences

**放弃的东西**

- 不做骨骼（P0–P3）。换装、换色都要重画帧 —— 这是为了"外部角色包透明可审"付的代价。若将来角色数量变多、换肤需求变强，再迁移到 Rive。
- 不做无限待机演出。角色大部分时间只有一个呼吸，这是刻意的：桌宠的价值是"在场"，不是"表演"。
- 不承诺"AI 一键生成角色包"。帧序列可以由工具辅助生成，但筛帧与修形必须有人。

**欠下的债 / 前置**

1. **美术产能是唯一真瓶颈**。技术方案再干净，没有三视图与几十帧动作，页面还是那个图标。需要明确：找画师 / 买现成角色包（确认授权）/ 用 AI 生成后人工修 —— 三条路选一条。
2. 现行 `AliCharacter.tsx` 在 P0 前不删：先用它占位，图集渲染器就绪后整体替换。
3. 角色包格式一旦分发出去就要版本兼容，manifest 必须有 `formatVersion` 与校验。

**Reintroduction conditions**（若将来要改用 Rive）

- 角色数量 > 3 且需要换装/换色；或
- 外部角色包需要非美术人员也能制作；或
- 现有图集包的体积超过 5 MB。

## 附录 A：用 AI 生成角色资产 —— 需要准备什么

这份清单回答一个问题：**不请画师、用 AI 出图，要交出什么样的东西才能接进运行时。**

### A1. 先定三件事（不定这三样，AI 只会给你 8 个不同的角色）

1. **角色是什么**：一句话 + 3 个可画出来的特征。例：「一滴悬浮的墨，两只小角，一圈断开的轨道环」。特征必须能被画出剪影认出来。
2. **风格锚点**：给 2–3 张参考图（大肥鱼那种：圆润 2D 平涂、单层硬阴影、外轮廓略粗、无渐变）。参考图比形容词有效十倍。
3. **色板**：≤6 色 + 1 强调色，给 HEX。**色板必须固定下来**，否则 AI 每张图都会微调，拼成图集后色偏肉眼可见。

### A2. 要生成的图（合计约 44 张，可砍到 11 张起）

| 批次 | 数量 | 规格 | 用途 |
|---|---|---|---|
| 三视图 | 3（正 / 侧 / 背） | 1024²，白底，同一站姿同一比例 | 定头身比、剪影、色板；不进运行时 |
| 表情集 | 8 | 512²，透明底，头部对齐 | 表情替换层（同一身体 × 8 表情） |
| 动作关键帧 | 8 动作 × 4 帧 = 32 | 512²，透明底，**脚底锚点在同一 y** | 图集（运行时资产） |
| 立绘 | 1–2 | 1024² | 空态页 / 关于页 |

**动作清单（P0 八件）**：`idle`（呼吸）、`think`（歪头托腮）、`work`（敲键盘）、`happy`（举手）、`alert`（竖角警觉）、`sleep`（趴下）、`wave`（招手）、`tilt`（疑惑）。

### A3. 一致性的三个层次（这是 AI 出角色帧的唯一真难点）

| 层次 | 做法 | 一致性 | 适用 |
|---|---|---|---|
| L1 | 纯文生图，逐张生成 | 差（会变成 N 个角色） | 只用于探索风格 |
| L2 | 固定 seed + 参考图（IP-Adapter / reference 权重）+ 局部重绘 | 中 | 表情集够用 |
| L3 | **训练角色 LoRA**（20–40 张：三视图 + 表情 + 关键姿态）+ **ControlNet 锁姿态** | 可用 | 动作帧必需 |

**推荐 L3**。LoRA 训练一次约 30 分钟–2 小时（看机器），之后所有帧用同一 LoRA + 同一 seed 起步，再用 ControlNet（Lineart 或 Depth）把姿态锁在你给的骨架上，最后人工修形。

**逐帧中间帧不要用 AI 生成**：会闪烁（同一角色每帧线条位置微漂移，播起来像在抖）。中间帧用 2 帧之间的"跨帧插值"或直接少画一帧——12 fps 的 4 帧动作，人眼补得过去。

### A4. 要喂给 AI 的输入（照这个填）

**① 角色设定卡**（先跑出三视图，后续所有图都带这张卡）

```
主体：<一句话形态>，两只小角，一圈断开的轨道环
风格：圆润 2D 平涂，单层硬阴影，外轮廓略粗，无渐变，无描边发光
比例：约 1:1 头身（Q 版），头占画面 60%
色板：#<主色> #<次色> #<线色> #<高光> #<阴影> #<强调>
材质：哑光，无金属无玻璃
背景：纯白（三视图）/ 透明（表情与动作）
排除：写实、3D、厚涂、渐变、发光、文字、水印、多角色、多余肢体
```

**② 三视图专用**：`character turnaround sheet, front view / side view / back view, same character, T-pose, white background, consistent scale, flat colors, no shading variation`

**③ 表情集专用**：`expression sheet, same character, 8 expressions: neutral / curious / focused / happy / alert / tired / confused / proud, identical head angle, transparent background, consistent line weight`

**④ 每个动作的姿态描述**（文字即可，若能给火柴人草图更好，直接当 ControlNet 输入）

例 `work`：`sitting, leaning forward, both hands on a small keyboard, ears relaxed, eyes on screen`
例 `alert`：`standing upright, ears/tips raised, eyes wide, body tilted slightly forward`

**⑤ 负面提示词**：`multiple characters, text, watermark, extra limbs, background scenery, realistic, 3d, gradient shading, blurry edges`

### A5. 出图后必须做的四步（不做就接不进运行时）

1. **抠图**：rembg / BiRefNet，检查边缘无白边（halo）。白边在深色主题下会变成一圈脏光。
2. **对齐锚点**：所有动作帧的**脚底统一到同一 y**、身体中心统一到同一 x、朝向统一朝右（镜像在运行时做）。
3. **限色**：把整批图统一压到那 7 个颜色。AI 每张图的阴影色会偏 2–5%，拼起来就是"脏"。
4. **打包**：图集 + `atlas.json`（每帧 `x/y/w/h` + 锚点）。用 TexturePacker 或自写 node 脚本，不要手填。

### A6. 每张图的验收清单（逐条打勾）

- [ ] 缩到 48px 还能认出是同一个人（剪影测试）
- [ ] 与三视图的比例误差 < 5%（同一把尺子量头身）
- [ ] 透明边缘无白边
- [ ] 颜色只用了色板里的色（取色器抽查）
- [ ] 脚底锚点与同动作其它帧一致
- [ ] 相邻帧轮廓差异明显（叠图能看出动作推进，否则白画）

### A7. 不要交给 AI 的部分

| 不交 | 谁做 | 原因 |
|---|---|---|
| 逐帧中间帧 | 少画一帧 / 人工补 | AI 逐帧会闪烁 |
| 图集坐标 | 打包脚本 | 手填必错 |
| 动作元数据（条件/权重/冷却） | 人写 | 这是设计判断 |
| 台词 | 人写 | 要与状态同步 |
| 最终线稿修形 | 人工（哪怕只修 10 分钟一张） | AI 的手指/角/环这类细结构最容易崩 |

### A8. 工具按环节选

| 环节 | 可选 |
|---|---|
| 立绘 / 三视图 | SDXL、Flux、即梦、Midjourney |
| LoRA 训练 | kohya_ss（本地）、云训练服务 |
| 姿态控制 | ControlNet OpenPose / Lineart / Depth |
| 局部改表情 | Inpaint（SD / Photoshop 生成式填充） |
| 抠图 | rembg、BiRefNet |
| 打包 | TexturePacker、自写脚本 |

本仓库已有一个 `image_gen` 工具，可以直接用来跑第一版草稿（探索风格足够，正式资产仍建议上面这套流程）。

### A9. 工时估算（一个人，不含返工）

| 步骤 | 时间 |
|---|---|
| 定角色 + 三视图定稿（含试错） | 1 天 |
| LoRA 训练 + 调提示词 | 半天 |
| 32 帧生成 + 筛选 | 2–3 天 |
| 修形（每张 10 分钟 × 32） | 2 天 |
| 抠图/对齐/限色/打包 | 半天 |

**合计约 1 周**。若砍到最小版（8 表情 + 3 姿态 = 11 张），约 2 天。

### A10. 最小可行替代（不训 LoRA 的走法）

只用**一张高质量立绘 + 局部重绘**产出：

- 1 张正面立绘（定稿）
- 8 个表情 = 同一张图上只重绘眼部区域
- 3 个姿态（idle / work / alert）= 对同一张图做局部重绘改身体倾斜与手部

一共 11 张图、一致性靠"同一张底图"保证。够撑起 P0 的视觉验收，之后再补 LoRA 与完整动作集。

**这条路的真正门槛不是技术，是那三件输入（形态、风格参考、色板）。** 给了这三样，剩下的都是流水线。
