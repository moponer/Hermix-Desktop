# Decision Note: 手机端继承桌面模型配置、凭据出电脑的授权模型与本地直连

Status: implemented — 手机端模型清单与凭据经既有密封 WS 帧由桌面推送（默认关闭，需桌面端显式开启）；关闭即撤销、手机连带删除本地那份；电脑离线时手机可本地直连云厂商继续纯对话。

前情：[2026-10-18-mobile-link-hardening](../../proposed/architecture/2026-10-18-mobile-link-hardening.md)（同一条链路的大计划，本文只处理「模型配置与凭据」这一段）、
[2026-10-11-relay-structured-deployment](../architecture/2026-10-11-relay-structured-deployment.md)（relay 的产品注册表里没有通往节点的 HTTP 通道）、
[2026-10-14-mobile-voice-input](../feature/2026-10-14-mobile-voice-input.md)（本文沿用它的「桌面配置 → WS 密封帧下发手机」范式）、
[2026-10-15-phone-revoked-credential-terminal-state](../bug-fix/2026-10-15-phone-revoked-credential-terminal-state.md)（撤销判活，本文在其上补「连带清本地凭据」）。

## Decision

### 1. 手机端模型清单与凭据一律走既有密封 WS 帧通道

桌面在手机连上时推一份 `model.list` 快照（已启用模型 + 默认模型 + 这些模型用到的 provider 凭据）。
手机端不保留第二份模型配置 UI，也不自己存权威清单——清单的唯一真相源在桌面
（`config.yaml` 的 `model_selector` / `llm_providers`），手机持久化的只是一份快照。

中继不为这件事变成 HTTP 网关：手机此前调 `GET {relay}/api/model/list`，而 relay 是只路由的
字节管道、没有通往节点的 HTTP 通道，那条请求必然 404，模型选择器因此永远是空的。

### 2. 推凭据是显式授权，默认关闭

`StreamEvent::ModelList` 里带的是真凭据（provider 的 `base_url` + API Key）。这不是模型名单，
是一把电脑关机也还有效、能烧钱的独立钥匙——它不像其它配对能力那样随电脑一起失效。
所以它默认不做：开关落在 `$HERMIX_HOME/mobile_model_push.json`（文件缺失或解析失败 = 关闭，fail-closed），
桌面端在「手机连接」面板用 `GET/PUT /api/mobile/model-push` 切换。

只推已启用模型实际用到的 provider：推得越少，手机持有的密钥面越小。
### 3. 「关闭」是撤销，不是「不再推」

关掉开关后，电脑推给手机的是一份空清单；手机据此删除本地存的那份（含 API Key）并提示
「电脑端未启用模型配置推送」。只停推而不清手机那份，等于给人假安全感——用户以为收干净了，
手机其实还在拿着旧 key 照用不误。

### 4. 撤销配对时手机连带清掉本地凭据

凭据被撤销（401 / 已被中转拒绝）是终态，手机就地清空本地模型配置。撤销的语义是
「这台设备不再持有访问权」，留着 key 等于只撤了一半。

### 5. 本地直连是第二条独立路径（电脑离线时用）

手机用推来的凭据直接向云厂商要答案（OpenAI 兼容的 `/chat/completions`，SSE 流式），
不经过 relay、不经过电脑——relay 的职责是「把手机的消息转到你的电脑」，这条路上没有电脑。

本地对话只有纯对话：没有工具、没有审批、不落电脑的会话库。通道选择由手机端顶栏的
「自动 / 仅电脑 / 仅本地」决定，「自动」= 电脑在线走电脑、否则走本地。

本地增量转成同名 App 事件喂给同一个 reducer（`assistant.message` / `turn.done` / `turn.error`），
于是打字机、淡入、markdown 渲染、气泡落定全部复用现有管线——不写第二套渲染。

### 6. 中继帧必须先摊平，错误帧必须带出原因

两处是同一条链路上的静默故障：

- `mobile_protocol::to_mobile_frame` 此前只读顶层 `type`，而中继实际发的是嵌套 `WsEnvelope`
  （`{event:{type:...}, seq}`）——于是所有 agent 事件被静默丢弃，手机端连助手回复都收不到。
  现在先取 `event` 层再映射。
- `StreamEvent::Error` 的字段是 `code` / `message` / `detail`，没有 `content`；映射此前只透传
  `content` → 手机端永远显示兜底文案「出错了」，真实原因（LLM 401 / 参数非法 / 5xx）被整个吞掉。
  现在这三个字段一并透传。

## Alternatives considered

| 方案 | 否决理由 |
|---|---|
| 让 relay 反代手机的 `/api/*` 到节点（HTTP 隧道） | 破坏 relay「字节级透传、不解析不授权」的核心不变量：把哑管道变成有语义的代理，攻击面显著扩大。改走已有密封帧通道，relay 对内容依旧无知。 |
| 手机端自建模型配置 UI，用户在手机上填 API Key | 用户明确不要手动配模型；且手机存的 key 与桌面那份必然漂移，两处真相源迟早打架。 |
| 推凭据但不设开关 | 凭据出电脑是长期有效、能烧钱的独立凭据，必须由人在电脑上按一次。默认不做是唯一站得住的默认值。 |
| 开关关闭时只「不再推」、不清手机本地那份 | 假安全感：用户以为收干净了，手机还在用旧 key。撤销语义要求两边同时收回。 |
| 手机端跑端侧模型（离线小模型） | uni-app 拿不到原生运行时，需要 UTS 插件（llama.cpp / MLC）——另一个量级的工程，且与零安装定位冲突。 |
| 本地直连另写一套渲染管线 | 转成同名 App 事件喂现有 reducer，零第二套 UI，也零第二套状态机。 |
| 撤销配对时由 relay 推一帧通知手机清凭据 | 撤销后手机已经连不上，推不到。改用手机端已有的「凭据被拒 = 终态」判据就地清理（见前情那篇撤销判活笔记）。 |
| 拆成「推清单」与「推凭据」两个独立开关 | 暂不拆。先把推不推凭据这件事变成显式授权；清单本身不含密钥、危害面小，等真有人抱怨「我就想看看模型列表」再拆。 |

## Consequences

**得到**：

- 手机端继承桌面模型清单（此前恒为空，因为那条 HTTP 请求必然 404）。
- 电脑关机后手机仍能对话（纯对话），且用户全程不用在手机上配任何模型。
- 凭据出电脑从默认行为变成显式、可撤销的授权，且撤销在两端同时生效。
- 失败原因不再被吞：手机端显示桌面给的真实 `message`，不再是无信息量的「出错了」。
- 中继仍是只路由的字节管道——新增能力没有给它增加任何理解内容的能力。

**代价 / 放弃**：

- 手机端明文存 API Key（uni-app 拿不到 Android Keystore）。当前防线是「默认关 + 随时可撤 +
  厂商侧可轮换」三层；真正的加密存储要等 UTS 原生插件那条线。
- 本地对话只有纯对话：没有工具、没有审批、不进电脑的会话库、不参与电脑侧的记忆与压缩。
- 多出三个跨端概念：`StreamEvent::ModelList` 事件、`/api/mobile/model-push` 开关、手机端的通道选择。
- 中继仍是单点：本地直连只在电脑关机时兜底，relay 挂了且电脑开着时手机依旧不可用。
- 手机端不再有「配置模型」这一 UI——这是有意的代价：省掉一份必然漂移的副本，也省掉用户在
  手机上填 API Key 的糟糕体验；代价是「想换 provider」必须在电脑上做。

**未做**：

- 端侧模型（离线小模型）——需 UTS 原生插件。
- relay 侧的 HTTP 隧道（本文明确否决的方向）。
- 手机本地配置的加密存储（需 Keystore 插件）。
- 手机端直连的会话持久化与多轮上下文裁剪。
