# Decision Note: 手机端配对语义是 N:1——每台桌面同时只被一台手机连着

Status: implemented — relay 路由与签发口都改为单槽，旧的多手机用例已按新契约重写

## Decision

配对关系是 **N:1**，不是 1:1 也不是 N:N：

- **手机 → 桌面是多对多**：一台手机可以连多台桌面（家里、公司），这也是这个功能
  存在的理由。
- **桌面 → 手机是 1 对 1**：每台桌面**同时只允许一台手机**接入。换手机必须先在
  桌面端撤销原设备，否则那台旧手机会一直收着这台电脑的广播帧。

三处共同保证这条语义：

1. **relay 路由单槽化**（`apps/relay/src/router.js` `attachPhone`）。原来按 token
   哈希去重、**多条并存**，`nodeToPhones` 把出站帧广播给全部——等价于一台电脑的
   会话内容同时流向任意多台手机，只要其中一条凭据泄露就全暴露。改为：一个 node
   的手机槽至多一条，**别的**凭据来占位直接拒绝。同一 token 的重连照旧放行（那是
   手机自己的断线重连，不是换人）。
2. **签发口也拦**（`server.js` `/api/relay/issue-phone`）。只在握手处拦不够——凭据
   已经发出去、对方拿着它反复重连，每次都被拒，桌面端却还在正常出码，排查极难
   定位。真正的拦截点是「这台电脑现在是否已经有一台手机连着」，命中返回 409 与
   明确文案。
3. **拒绝而非顶替**。理由与 `attachNode` 已有的 conflict 分支完全一致：静默踢掉
   受害者等于让凭据泄露者直接接管那台电脑。顶替还会把「先撤销」这个显式动作抹掉，
   而那正是这条安全语义的要点。

配套：桌面端出码失败时直接显示 relay 的原话（`relay_settings::issue_phone_credential`
取 JSON 的 `error` 字段而不是整段 body），不再统一报「出码失败」。

## Alternatives considered

| 方案 | 为何否决 |
|---|---|
| 新手机顶替旧手机 | 凭据泄露即可直接接管那台电脑，等于取消「先撤销」这道显式闸门。且与既有 `attachNode` 的 conflict 语义自相矛盾——那处特意拒绝静默踢掉真电脑。 |
| 只在握手处拦，签发口不管 | 凭据已发出，对方面对的是「一直重连一直被拒」而桌面端毫无提示，故障现场无法定位。 |
| 保留多槽，仅在 UI 上限制 | UI 限制挡不住任何直接调 `/relay/phone` 的客户端——安全语义必须在服务端。 |
| 把多手机下沉到会话隔离（每台手机独立 sid） | 那是「多手机各自独立会话」的模型，与「每台桌面只被一台手机连着」是两回事。本项目要的是后者：连通性上就只允许一台。 |
| 保持 `phoneConns` 为 Map 但加长度检查 | 不变 Map 语义就等于把不变量交给每次写入点维护。取「遍历取值」而非直读某个键，是为了让单槽这条不变量一旦被写坏就立刻暴露，而不是悄悄按 Map 语义跑下去。 |

## Consequences

- 一台电脑同时只服务一台手机。**换手机是显式两步**：桌面端撤销原设备 → 重新出码。
  这是本次刻意付出的代价，也是安全语义要求的。
- 旧凭据撤销后槽立即空出，新手机才接得上——`dropPhone` 与 `attachPhone` 的配合
  顺序即换机路径，已用单测钉住。
- `NodeSlot.phoneConns` 仍是 Map 而非裸字段：`dropPhone` / `detach` 两处按凭据
  定位的既有逻辑不用改。不变量由 `attachPhone` 单点维持。
- 移动端若已连着某台桌面而用户想用另一台去连它，会拿到明确的 CLOSE 帧
  （`desktop_already_paired_with_another_phone`，close code 4009）而不是连上后
  收不到消息。
- **这次改的是 relay 服务端**，桌面端只改文案与错误呈现。发布时 relay 与桌面端
  需同时更新：桌面端单独更新会先撞上新的 409 报错（文案已能正确呈现），relay 未
  更新则语义不变。

## 验证

- `apps/relay` 测试：35 条 34 通过。两条旧用例断言的是被本决策推翻的 N:N 语义
  （「多台手机全部投递」「dropPhone 不影响另一台」），已按 N:1 重写，并新增
  「第二台手机被拒」「同一凭据重连带顶掉自己」两条。
- 剩余 1 条失败与本改动无关：安装页用例断言首页含 `Hermix M`，而并行工单在
  `apps/relay/public/mobile.html` 的未提交改动里删掉了该字符串（HEAD 中存在）。
- `tsc --noEmit` exit 0；`npx impeccable@4.1.0 detect` 对改动界面文件 exit 0。
- `cargo test -p hermix-server --lib` 见提交信息。
