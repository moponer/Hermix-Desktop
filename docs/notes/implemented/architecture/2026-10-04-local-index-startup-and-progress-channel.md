# Decision Note: 本机文件索引的启动时机与进度通道

Status: implemented — 启动即后台建索引；进度走独立轻量命令，不再重跑匹配

## Decision

`commands_local_search.rs` 的本机文件索引按下面两条规则组织。

**1. 什么时候建索引：应用启动就跑，但自动路径不回退 jwalk。**

`start_background_index()` 在 Tauri `setup()` 里被调用，走 `ensure_index(false)`。
`allow_jwalk_fallback=false` 意味着：提权 helper（MFT/USN，秒级）不可用时
索引留空、扫描就此打住，**不退**化成 jwalk 全盘遍历。

这条规则来自一条物理约束：MFT/USN 原始读取必须管理员权限，而 jwalk 是唯一
的无授权兜底，它在几分钟内把整盘读一遍。自动工作发生在用户尚未表达任何意图的
时刻（刚打开应用），这时把磁盘占满是不可接受的代价；而用户真的打开查找面板、
敲了字，那份代价是他自己要的，理应由他触发。**自动工作只做「便宜或不做」。**

用户显式查询（`local_search`）仍走 `ensure_index(true)`，保留 jwalk 兜底 ——
功能不因为自动路径保守而缩水。两条路径的分工只差这一个 bool。

`HELPER_FAILED` / `AUTO_SCANNED` 两个原子标志保证：helper 在本进程内失败一次
（UAC 被拒 / exe 缺失 / 非 NTFS / 超时）就不再重试。少了它，每次启动自动扫描
和每次打开面板都会重新弹一次 UAC —— 骚扰用户，且在无 helper 的机器上纯空转。

**2. 进度怎么到 UI：独立的只读状态命令，不复用查询。**

新增 `local_search_status()`，只读 `building` 与 `indexed` 两个计数器后返回。
前端在 `building` 为真时每 500ms 调它，索引建成那一刻 `building` 翻假，再
重跑一次完整查询拿最终结果。

原先 UI 只有 `local_search` 一条通道，而它只在 query/筛选**变化**时才被调用。
后台扫描是异步的、UI 侧无事件，于是「已发现 N 项」永远停在下一次输入时的
快照值 —— 表现为截图里的「已发现 0 项」不动。

## Alternatives considered

- **轮询直接调 `local_search` 刷新进度**：每次轮询都会重跑一次 nucleo 模糊
  匹配。百万级条目下单次匹配是几百毫秒 CPU，每 500ms 一次会把 CPU 烧在
  用户看不见的地方。用「数字会动」换「界面卡顿」是负收益，故拆出只读通道。
- **Rust 侧加 Tauri event 推送进度**：能省掉轮询，但要给 `Index` 加观察者、
  给 AppState 加字段、给前端加 `listen` 生命周期管理。三处改动换 500ms 的
  延迟，当前规模下不划算。轮询在扫描结束后自动停（依赖里只放 `status?.building`），
  建成之后是零开销。
- **把索引持久化到磁盘，启动时直接读缓存**：这才是根治（启动零成本、无 UAC），
  但要处理 300MB arena 的序列化格式与版本失效，是独立的一块工作，不在本次范围。
  当前的取舍是「每次冷启动一次 UAC 换取秒级索引」。
- **自动路径也允许 jwalk 兜底**：省掉「索引建不起来就是空的」这个状态，但等于
  用户什么都没做就让他等一次全盘扫描。上面第 1 条的物理约束直接否掉它。
- **给自动扫描加设置开关（默认开/默认关）**：一个 bool 的默认值不足以定夺
  产品语义，且引入配置项就要配套 UI、持久化、迁移。先按「开」交付，
  真要关是一行 `setup()` 注释的事。

## Consequences

- 冷启动会弹一次 UAC。这是 MFT/USN 路线在当前权限模型下的固有成本，不是本
  决策引入的新负担 —— 此前它发生在第一次打开查找面板时，现在提前到启动时。
- 提权被拒的机器上，索引在本次会话内始终为空，打开面板会走 jwalk 慢路径
  （与改动前一致），但不再反复弹 UAC。
- `indexed` 在扫描期间是估算值（helper 路线按 snapshot 文件大小 ÷ 90B 推算，
  jwalk 路线是精确计数），建成瞬间跳到真实条目数。UI 文案保持「已发现 N 项」
  而非「已索引 N 项」，正是为了不承诺这个数字在扫描中精确。
- `rebuild_index` / `ensure_index` 都多了一个 bool 参数，调用点只有三处。
