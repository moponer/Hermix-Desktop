# Decision Note: 免费渠道两个自动路由常驻启用清单 + 失效模型三处闭环摘除

Status: implemented — 2026-10-25 落地；hermix-config / hermix-server / 桌面前端同批交付

## Decision

### 1. 自动路由不参与 Top-N 竞争，但始终进启用清单

开箱默认启用清单 =「上下文最大的前 5 个免费模型」（`seed_default_free_models`
的 Top-N）。新增 `AUTO_ROUTE_MODELS = ["openrouter/free", "kilo-auto/free"]`
（hermix-config）：这两个跨免费池的**自动路由**在 Top-N 选完后追加进启用清单
（已在 Top-N 里则不重复），且 `kilo-auto/free` 补进 Kilo 的 seed_models（首启
离线即可选）。理由：具体免费模型随上游上下架来去，聚合路由是免费池里最稳的
兜底入口，不该被上下文数值挤出启用清单。

### 2. 失效免费模型的摘除从「半闭环」补成「三处闭环 + 401」

此前只有聊天中 404 `does not exist` 触发摘除，且 `remove_dead_model` 只清
provider 目录（`model` CSV / contexts / meta）——`build_model_list` 的启用清单
不按目录过滤，死模型于是从「可添加」里消失、却永远留在聊天下拉里；401 则
完全不在闭环里（免费路由匿名可调，401 = 路由被上游关掉，同样是死信号）。

现在：

- **摘除范围三处一起清**：provider 目录、`model_selector.enabled`、指向死
  模型的默认模型 / 顶层 `model`（重指到剩余启用首条）；付费 provider 的
  同名模型不受影响（按 owning provider 限定）。
- **401 纳入聊天时闭环**（App.tsx）：仅当当前会话模型是 `custom-free-*`
  前缀时上报——付费厂商 401 是用户自己的 key 问题，摘模型等于掩盖真问题。
  后端 `remove_dead_model` 本就只动免费渠道，前端前缀判断是语义双保险。
- **设置页免费行的「测试」改为 1-token 真实推理探测**（新端点
  `POST /api/free-channel/probe-model`）：`GET /models` 只能测网关连通，
  测不出单个免费模型的死活。探测 401/403/404 → 自动上报摘除并刷新列表
  （死行当场消失）；限流/超时只提示、不摘。
- **自愈回路**：摘除不是流放——启动刷新「只增不删」，上游若重新上架同名
  模型，下一次 `/models` 刷新会把它加回来。

### 3. 自动更新现状（结论，不改架构）

模型清单自动更新**存在**：启动 20 秒后刷新（`refresh_on_start`，默认开）
合并上游 `/models`（每渠道 ≤8 条新增），上下文与能力一并更新；设置页手动
刷新复用同一入口。缺口不在「不更新」，而在「失效不摘除」——由上文第 2 条补齐。

## Alternatives considered

- **路由也按上下文参与 Top-N**：否决——路由的 context 数值是网关自报的
  聚合值，与具体模型不可比；路由的存在价值是稳定性，正是不该被挤出去的。
- **401 一律摘除（不限免费渠道）**：否决——付费厂商 401 是 key 失效，
  摘模型会让用户以为「模型没了」而真实问题是配置。
- **探测端点顺带自动摘除**（一次调用完成测+删）：否决——探测是诊断、摘除
  是写操作，两者分开前端才能在限流/超时时只提示不删；也复用既有
  `dead-model` 上报链路，不另开第二条写路径。
- **启动时对全部启用免费模型逐个探测、预防性摘除**：否决——把 N 次推理
  请求放进启动路径，慢且烧配额；按需（测试 / 聊天失败时）闭环已覆盖真实
  场景。
- **连续失败计数（如连续 2 次 401 才摘）**：否决——需要跨进程持久计数器，
  复杂度换来的防抖收益有限：摘除可被刷新自愈（上游重新上架即回来），
  一次 401 摘错的代价远小于计数器的维护成本。

## Consequences

- 新装环境启用清单 = Top-5 具体模型 + 2 个自动路由（最多 7 个免费条目）。
- 已装环境（`defaults_seeded` 已置位）不重跑 seed：用户在设置页手动启用过
  的路由照旧；想要新行为可手动加或重置配置。
- 设置页免费行「测试」现在真实调用一次上游推理（匿名网关、1 token），
  测试失败提示从「HTTP 401」升级为「已失效，已从列表移除」。
- `remove_dead_model` 的语义从「清目录」扩为「目录 + 启用 + 默认」，是既有
  `POST /api/free-channel/dead-model` 端点的行为变更，前端无需改动调用方。
