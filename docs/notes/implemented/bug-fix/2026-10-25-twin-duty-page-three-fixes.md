# Decision Note: 阿黎值守页三修——stdio 漏挂巡检、任务台嵌窄容器排版、会话列表可操作

Status: implemented — 2026-10-25 落地；hermix-server（stdio 装配）与桌面前端同批交付

## Decision

用户在阿黎值守页「任务」页签实报三件事，三个根因、三处修复：

1. **「团队」「资源」两个页签永久骨架屏**——双层根因：
   - 后端：桌面端 sidecar 走 `hermix --stdio`，其 state 构造**漏挂
     `with_resource_patrol()`**（只挂在 HTTP 模式 `run_server` 上）→
     `GET /api/resource/patrol` 恒 503。与 relay client 当年漏挂是同一类坑
     （stdio 与 run_server 两条装配路径必须逐个对齐 builder）。
   - 前端：`refreshStatic` 用 `Promise.all` 绑三个端点，一个失败 →
     `roles`/`patrol` 永远停在 `null`，而骨架屏的渲染条件恰是 `=== null`。
   - 修复：stdio 路径补挂巡检；前端拆成三路独立请求，失败的那一路就地显示
     「哪一路失败 + 重试」（60s 自动轮询照旧），成功路照常渲染。**骨架屏只
     在首次加载进行中出现**，失败必给可读信息——「永远加载中」从此不可能。

2. **工单四列看板在值守页窄容器里排版挤爆**——嵌入态（`embedded`）不再复用
   宽页的四列网格：改为**按状态分组的紧凑单行列表**（只显示非空组，一行一单，
   点开详情/中止不变）；独立「任务台」页保持四列看板。宽窄两个形态共用
   `MemberCard` 组件，卡体不再两处复制。

3. **「最近会话」只摆标题、不可点不可删**——行主键改为按钮：点行 =
   `handleSelectSession`（切过去并回对话页正文）；行尾删除钮 =
   `handleDeleteSession`（复用宿主的乐观删除）。日志行（「最近工作日志」/
   「刚才发生」）保持只读——它们没有可打开的正文目标。

## Alternatives considered

- **巡检 503 时前端降级显示假快照**：否决——把后端装配错误藏进前端兜底，
  错的那一层永远修不好。让错误可见（503 → 错误面板）+ 修装配才是闭环。
- **`Promise.allSettled` 替代拆分**：能让成功路渲染，但失败路仍无独立状态
  可表达「哪一路、为什么、怎么重试」；拆成三路是同成本更明确的结构。
- **嵌入态继续用网格但改两列**：否决——两列在 ~700px 里仍是窄卡换行；分组
  列表才与「值守中轴」的信息密度匹配（参考侧栏最近会话的行密度）。
- **会话删除做成 hover 才出现的图标**：否决——用户明确要「能删」，可发现性
  优先；删除钮常驻但弱色，hover 转错误色。

## Consequences

- 桌面端重启后「资源」页签显示真实巡检快照（停派门 / C 盘水位 / 配额），
  不再 503；即便未来某端点再坏，UI 显示具体错误与重试，不再永冻。
- `run_server` 与 stdio 两条装配路径今后新增 builder 时必须两边同步——
  本笔记是第二次同类事故的存证（第一次是 relay client）。
- 「最近会话」删除即时生效（乐观更新），失败回滚并 alert。
- 嵌入态任务台的「空」占位不再渲染：空组直接整组隐藏，由组计数表达。
