# Decision Note: 截图编辑器窗口下限 —— 小选区不再把工具条挤进图像里

Status: implemented — 2026-10-28 交付：编辑态窗口不小于 560×280（CSS 逻辑像素），
窗口自带暗底，图像在工具条上方的舞台里等比适配

## Decision

现象（用户 2026-10-28）：框一小块区域（几十像素见方）后，整个编辑工具条被挤进
截图区域，按钮压成竖排字、右侧动作被切掉。

根因是「**选区即窗口**」这条 2026-10-23 的结构决策走到底：`screenshot_select`
把覆盖窗 `set_size` 成选区物理尺寸，于是选区 40×30 时窗口就是 40×30。工具条
（6 工具 + 6 色板 + 3 档笔宽 + 3 动作，自然宽度 ~764px）在 40px 宽、30px 高的
窗口里只能被压扁 —— 2026-10-26 那轮 CSS 修复（`flex: 0 0 auto` +
`white-space: nowrap` + `flex-wrap: wrap`）只能保证「不被压成竖排字」，救不了
「没有空间可换行」。

修法分三层，缺一层都不成立：

1. **Rust 兜底最小窗口**（`screenshot_controller.rs`）：`EDIT_MIN_W_CSS = 560` /
   `EDIT_MIN_H_CSS = 280`，按 `win.scale_factor()` 折算成物理像素。新增纯函数
   `edit_window_rect(sel, bounds, min)`：以选区为中心左右上下各摊一半做外扩，
   再 `clamp` 回虚拟桌面内（窗口探出桌面 = 看不见也点不到的死区）。桌面比下限
   还小时贴桌面左上角。
2. **编辑器自带暗底**（`.se-root` 的 `--se-surface`）：窗口是透明的，放大后多
   出来的那一圈必须自己填色，否则露出活桌面 —— 这既是观感问题，也是旧笔记当初
   否决「撑大窗口」的第一条理由。`--se-surface` 是覆盖窗本地令牌（编辑器恒为
   暗色工作台，不随主题），与工具条的暗底同源。
3. **版面重排成「舞台 + 工具条」两段**：`.se-toolbar` 从 `position: fixed` 悬浮
   改成流内元素，新增 `.se-stage` 吃掉剩余高度、画布在其中等比居中。工具条多高
   （窄窗下会换行）图像区域就自动让出多少 —— **工具条不再压在图像上**。显示尺寸
   改为量 `.se-stage`（`ResizeObserver`）而不是猜 `window.innerHeight`。

上限仍是 1:1 物理：小图不放大（放大一张 40×30 的截图只会得到一片马赛克），
大图在舞台内等比缩进。

## Alternatives considered

- **只放大窗口、版面不动**（工具条继续 `position: fixed` 悬浮在画布底部）：
  改一行就能让工具条「有地方站」，但工具条仍然压在图像下缘 —— 用户框的正是
  那一小块，遮掉一行像素比挤成竖排更糟。
- **给窗口设系统级最小尺寸**（`set_min_size`）：覆盖窗在选区阶段必须是整块
  虚拟桌面，最小尺寸会卡住第一阶段，且销毁重建才恢复。改成 `screenshot_select`
  里一次性算目标矩形，语义更窄也更准。
- **用 CSS `max-width/max-height: 100%` 让画布自适应**（省掉 JS 量测）：
  替换元素的 intrinsic ratio 确实能等比收缩，但 `getBoundingClientRect` 坐标
  映射依赖「元素盒子 = 内容盒子」，一旦某处退化成 letterbox（`object-fit` 或
  盒宽高与内容不同形），画笔/箭头坐标就整体偏移。保留显式内联宽高。
- **小选区时把图像放大填满窗口**：工具条问题解决得更彻底，但 40×30 的截图
  放大 10 倍是马赛克，用户会误以为自己截到了那块区域的全部细节。

## Consequences

- 编辑态窗口尺寸不再等于截图尺寸：小选区会看到一圈暗底（图像居中，工具条在下）。
  这是「工具条需要固定空间」与「图像 1:1」两条约束的必然交点。
- 窗口上限仍是虚拟桌面：选区贴近桌面右下角时，外扩部分被夹回桌面内，图像因此
  不总在窗口正中（偏左/偏上）。窗口既不能探出桌面，也不可能同时满足「居中」，
  选择保可用性。
- 大选区（>下限）现在也会让出工具条高度，图像显示比之前小 ~40px（`280` 档
  以上按工具条实际高度，通常 ~44px 单行）。换来的是工具条永不压住图像内容 ——
  2026-10-26 笔记里「窄选区时依然会遮住图像下缘」这条固有代价就此消掉。
- `EDIT_MIN_*` 是 CSS 逻辑像素常量，工具条若再增删控件需同步复核（工具条仍在
  ~520px 宽换两行，560 给了 40px 余量）；`edit_window_rect` 的 6 个单测覆盖
  等于选区 / 居中外扩 / 贴右下角 / 负坐标副屏 / 桌面小于下限 / DPI 折算。
