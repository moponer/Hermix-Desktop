# Decision Note: 截图标注尺寸按「屏幕像素」定 —— 大截图里文字只有 4.4px，"看不到"

Status: implemented — 2026-10-28 交付：字 / 线宽 / 笔刷按显示尺寸定义再换算成图像
像素；文本输入框固定 220×30 并在贴边时翻转；舞台不再裁掉浮层

## Decision

现象（用户 2026-10-28）：「截图上输入文本看不到啊，输入的文本呢」——文本工具
能输入了（见
[2026-10-28-screenshot-text-tool-mousedown-blur.md](2026-10-28-screenshot-text-tool-mousedown-blur.md)），
但输入框里的字和落字后的字都几乎看不见。

### 根因（实测）

标注尺寸是按**图像物理像素**定的：`TEXT_PX = 20 × devicePixelRatio`。而预览是
把整张截图缩到窗口里显示（`disp.k` = 每物理像素对应几个 CSS 像素）。两者相乘
就是用户在屏幕上看到的字号：

| 截图尺寸 / 窗口 | disp.k | 旧字号（屏幕） | 新字号（屏幕） |
| --- | --- | --- | --- |
| 300×200 @ 560×280 | 0.86 | 17.2px | 20px |
| 4000×2000 @ 900×620 | 0.221 | **4.4px** | 20px |

实测（vite dev + Edge + playwright 截图）：4000px 宽的截图里，输入框高 10px、
字号 4.42px，提交后画布上只有一小团红色噪点 —— 就是用户说的"看不到"。
同一算式也吃掉了线宽（4px 的框在屏幕上只有 0.9px，细成发丝）与马赛克笔刷。

### 修法

1. `pxForDisplay(cssPx, dpr, dispK) = cssPx / dispK`（`dispK <= 0` 时退回 dpr）：
   把「屏幕上多大」翻译成「图像里多少个像素」。字 `TEXT_CSS = 20`、线宽
   `strokeW`、笔刷 `strokeW × 4` 全部走它 —— 所见即所得：屏幕上 20px 的字，
   在 4 倍缩小显示的截图里就是 90 个物理像素。
2. 文本输入框字号固定为 `TEXT_CSS`（不再乘 `disp.k`），与落字后的视觉大小一致。
3. 输入框改成固定 220×30：`<input>` 默认宽度约 20 字符（20px 字号下 267px），
   点画布右半边就顶出窗口，正在打的字被窗口边缘切掉。固定宽度后组件可以用
   `TEXT_INPUT_W/H` 直接算出「这一侧还放不放得下」，放不下就把框翻到点击点的
   左/上侧（实测四角点击：框全部落在窗口内）。
4. `.se-stage` 去掉 `overflow: hidden`：画布本身永不超出舞台，但输入框是贴在
   点击点上的浮层，裁在图像边界等于把正在打的字切掉；窗口边界由 `.se-root`
   的 `overflow: hidden` 兜住。

### 为什么不是"只把字号调大"

字号是唯一跟着缩放走的东西时才需要换算；只要按显示尺寸定义，缩放多少都
恒定 20 CSS px。把阈值改成"至少 12px"只会把小图的字也糊成一片，且线宽/笔刷
仍然消失。

## Alternatives considered

- **给字号设下限**（如 `max(12, 20×k)`）：输入框里能看清了，但落字尺寸与屏幕
  所见不一致（屏幕上 12px、图上 20px），标注在导出图里仍然偏小；线宽与笔刷
  也没救。
- **把标注尺寸直接按 CSS 像素画**（不换算）：`canvas` 是物理像素画布，直接按
  CSS 像素落笔会随 dpr 变小（4K 屏上细成发丝）——这正是 2026-10-23 那版引入
  `× source.scale` 的原因。
- **输入框保持自适应宽度、只做位置夹紧**：夹紧需要知道框宽，而框宽随内容变化；
  要么量 DOM 后二次布局（抖动），要么继续猜一个魔法宽度。固定 220px 让"放不
  放得下"变成一次除法。
- **输入框浮层挂到 `.se-root` 下用 fixed 定位**：能彻底摆脱舞台裁切，但坐标要
  从 `getBoundingClientRect()` 现算，等于把现在纯 CSS 的定位逻辑搬到 JS 里，
  收益只是省掉一条 `overflow` 声明。

## Consequences

- 同一句标注在"缩小预览"和"导出图 100% 查看"下**视觉大小一致**；代价是导出
  图里的字号随缩放放大（4000px 截图里是 90px）—— 这是所见即所得的必然结果，
  也是微信/QQ 截图的行为。
- 缩放到 1:1（截图比窗口小）时行为与改动前完全一致：`disp.k = 1` 时
  `pxForDisplay` 恒等，只是改成统一走一个函数。
- 输入框固定 220×30：长文本在框内横向滚动，不再随内容变宽。翻转定位只保证
  "框在舞台内"，不保证输入框与最终落字位置重合（落字仍在点击点）—— 这是
  "别把正在打的字切掉"与"落字位置可预期"之间的取舍，选了前者。
- `TEXT_INPUT_W/H` 与 `.se-text-input` 的 `width/height` 是**两处必须同步**的
  常量（TSX 里注释已标明）；改输入框样式时要一起改，否则翻转判断会偏。
- 舞台 `overflow` 从 hidden 变 visible：画布过大只可能出现在"刚量到尺寸"的
  一帧，那时会短暂溢出到工具条上方；换来的是输入框永不被图像边界裁切。
