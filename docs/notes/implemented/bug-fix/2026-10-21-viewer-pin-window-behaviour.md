# Decision Note: 钉住浮窗 —— 不置顶、贴边吸附、网格自动排版、共享渲染作用域

Status: implemented — 浮窗不再压住别的程序；拖到屏幕边缘自动吸附；多个浮窗按网格自动排版；浮窗内的预览与主窗口走同一套样式

## Decision

### 1. 取消 always-on-top

浮窗原本带 `always_on_top(true)`，结果是**别的程序无法显示到前台** —— 用户手动激活的应用被压在下面，连查看器自己都被遮住。浮窗改回普通 z 序（后开的窗在上面），打开时 `set_focus()` 一次即可。

### 2. 贴边吸附

窗口拖到屏幕工作区某条边 28pt 以内时自动吸上去（`snap_to_edge`，作用于 `WindowEvent::Moved`）。拖动过程中 Windows 会用自己的位置覆盖我们设的值，但**拖动结束后的最后一次 Moved 事件**会再走一遍吸附 —— 那时吸附生效。已吸到边上的窗口再次收到事件时算出的目标与当前位置相同，不再触发移动，因此不自激。

### 3. 多个浮窗按网格自动排版

旧实现是"每开一个就斜着错开 28px" —— 三个窗口叠在一起谁也看不见谁，等于没有排版。现在把工作区按 √n 切成近似正方的网格，按开启顺序填格（`tiled_position`）。摆位是**参考桌面端成熟的贴靠分屏做法**（Windows 贴靠、macOS Stage Manager、PowerToys FancyZones 同一思路）里最朴素的一种：格子等分，互不重叠。

浮窗顶部另加一条工具条（文件名 + 路径 + 「贴左 / 贴右 / 居中」三个预设），对应新命令 `pin_place`；不想拖窗口也能一键贴边。

### 4. 浮窗内预览走共享渲染作用域

浮窗的预览容器补上 `preview-pane` 这一层作用域。共享预览层的样式全部写成 `.preview-pane .xxx` 的后代选择器，没有这个祖先就等于没有样式 —— 表现为"浮窗里的 md 目录排版全乱"（目录与正文挤成一列、章节跑到最上面），表格也是同样症状。

## Alternatives considered

- **保留置顶但改成"仅对查看器置顶"**：Windows 没有"相对某个窗口置顶"的概念，做不到；而"用户激活别的程序时它能盖上来"是明确诉求，直接去掉置顶最简单。
- **用 Win32 的 WM_SNAPWINDOW / 磁吸**：需要子类化窗口过程，Rust 侧没有现成绑定；自己算四个边的吸附阈值是同一套物理约束，成本低得多。
- **浮窗位置交给用户自己拖，程序不排版**：多个浮窗仍然会叠在一起；自动排版的价值恰在"开第三个时它自己找位置"。
- **把浮窗改成主窗口内的分屏（tabs / 多窗格）**：那是另一种产品形态（不再是"钉在屏幕上随时对比"），超出本次范围。
- **给浮窗单独写一套预览样式**：等于让渲染层分叉；作用域缺失是"少了一层祖先"的问题，补一层比复制一套样式便宜得多。

## Consequences

- 浮窗不再压住别的程序，但也可能被别的窗口盖住 —— 这是"用户能控制前台"与"浮窗一直显眼"之间的取舍，取了前者。
- 贴边吸附是**边触发**的：用户手动把窗口停在离边 28pt 以内也会被吸附过去；阈值不可配置。
- 自动排版按**开启顺序**填格，关闭后重开同一路径会回到记忆里的位置（记忆优先于排版），可能出现两个浮窗位置重叠 —— 用户可以自己拖开。
- 浮窗多了一条工具条，窗口可用高度少约 28pt。
