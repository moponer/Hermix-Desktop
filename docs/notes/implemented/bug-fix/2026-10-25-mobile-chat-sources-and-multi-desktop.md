# Decision Note: 手机端三种对话来源 + 多电脑共存 + 模型推送即时生效

Status: implemented — 2026-10-25 落地；手机端（apps/hm）与 hermix-server 同批交付

## Decision

手机端（Hermix M）的对话界面从「单一对象」改为**三条显式来源**，并把三个
实报缺陷一并修掉：

1. **三来源模型（`ChatSource = 'ali' | 'desktop' | 'local'`）**
   - `ali` 阿黎：上行走 `{type:'send', text, target:'twin'}`，桌面侧路由到
     `twin:ali` 并固定她的人格（`ws.rs` 既有逻辑，手机端此前从未带过
     `target`——这就是「界面写着阿黎、答话的说 I am hermix」的根因）。
   - `desktop` 电脑：不带 target，投给设备通用会话（直接遥控电脑干活）。
   - `local` 本机直聊：不连电脑、不控制电脑、没有阿黎；用桌面推送的模型
     配置直接问云厂商（原「离线模式」重构为独立来源，不再藏在阿黎对话里
     的一个开关后面，会话也不再混进阿黎的历史）。
   - 对话页顶部常驻三段式切换条 + 一句话来源说明；来源是会话数据结构的
     一部分（`hermix.sessions` 的 `source` 字段），历史页按来源分组展示，
     另加「电脑上的项目」（桌面 `session.list` 推来的只读清单）。
   - 删除 `pages/ali/index.vue`：它和历史页职责重叠（两份会话列表 + 状态卡
     重复任务/审批 tab），是「功能混乱、职责不清」的主要来源。

2. **多电脑共存**：配对成功后**不再清掉其他已配对设备**（此前
   `pages/pairing` 有一段「只保留刚配上的这台」——用户看到的就是「连了
   新电脑，旧电脑消失」）。`core/pairing.ts` 的设备清单 + 顶栏切换面板
   本来就是多机设计；旧 token 被桌面撤销时切过去会 401 → 横幅「去处理」
   → 设备管理移除，出路明确，无需预防性清库。

3. **模型推送开关即时生效**：`HttpServerState` 增加
   `mobile_config_tx: watch::Sender<u64>`（配置版本号）；
   `put_mobile_model_push` 保存后自增，`handle_ws_stream` 每条 WS 会话
   `select!` 订阅——版本一动立刻给**已连接**的手机重推 `model.list`。
   此前只在手机连上/切模型时推，开关变更要等重连才可见。

4. **凭据字段穿透修复**：`mobile_protocol::to_mobile_frame` 的字段白名单
   补上 `providers`——此前 `model.list` 帧里的 provider 凭据（base_url +
   API Key）在 relay 边界被剥掉，手机端本机直聊永远报「没有凭据」。

配套修复（同一批暴露的潜伏问题）：
- `pages/chat` 的 `getChatSource` 此前**没有 import**（onMounted 运行时
  ReferenceError，会话恢复静默失效）；
- hm 的 `tsconfig.json` include 只有 `src/**`（页面/核心都在根目录），
  `vue-tsc` 是空转假绿灯——扩到真实目录并修完暴露的 15 个类型错误；
- 中断改为 WS `stop` 帧：REST `/v1/sessions/{sid}/interrupt` 有归属闸门
  （阿黎那轮跑在 `twin:ali`，403）；本机直聊返回本地 abort 句柄。

## Alternatives considered

- **给每条消息让桌面自动识别人格**（不带 target，靠提示词猜）：否决——
  路由目标是数据不是语义，猜错就是把话说给错的人；`target` 字段与桌面
  TwinView 共用同一条 `twin:ali` 会话，这是「两个入口同一个她」的既有设计。
- **保留「离线」开关、只改文案**：否决——开关藏在阿黎对话里，会话混存于
  `ali` 来源；用户要求的是「与电脑端没有任何联系的一般对话」这一**独立
  心智对象**，必须是独立的来源、独立的历史、独立的边界声明。
- **历史页用筛选器（全部/阿黎/电脑）**：否决——新手要先学会「筛选」才能
  找到阿黎；分组直出 + 每组自带说明，空态本身就是教育。
- **配对后清理被撤销的旧设备**（原方案）：否决——撤销是桌面端逐台发生的
  事件，手机端无法预知哪台被撤；预防性清库牺牲了正常设备的多机能力，
  换来的只是省一次 401 横幅。
- **模型推送用轮询**（手机定时拉）：否决——多一条路径、多一份电量与流量，
  而 watch 通道是进程内通知，零成本且即时。

## Consequences

- 手机端发往阿黎的消息落桌面 `twin:ali` 会话：**桌面 TwinView 与手机看到
  同一个她、同一份历史**（此前手机的消息进设备会话，桌面 TwinView 看不到）。
- 本机直聊的会话只存在手机上（`l` 前缀 id），不落任何电脑；「交给阿黎」
  的移交按钮是唯一出口。
- `to_mobile_frame` 白名单加字段=手机可见面扩大，未来给手机加任何下沉
  字段都必须同步这里（测试已把 providers 钉死）。
- watch 通道只在两帧之间被 select：正在跑的一轮结束前，推送最多延迟到
  该轮结束，不丢、不中断。
- 旧版手机数据迁移：无 `source` 的历史会话归 `desktop`（既有 normalize
  规则不变），`local` 为新增合法值。
