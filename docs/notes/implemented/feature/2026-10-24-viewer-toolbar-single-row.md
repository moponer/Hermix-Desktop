# Decision Note: 查看器工具栏两行合一行 —— 面包屑即地址栏

Status: implemented — 重量模式工具区从两行（路径输入框 + 面包屑/搜索）并为一行；窄窗（≤820px）时右侧开关组自动收进「⋯」弹出菜单

## Decision

文件查看器（`apps/viewer`）重量模式的顶部工具区改为**单行**，核心是
「面包屑即地址栏」：一颗药丸承载两种形态，路径只在界面显示这一遍。

### 1. 地址药丸：平时面包屑，点空白进编辑

- 平时显示面包屑（段=跳转，末段加重=当前目录），尾部带复制按钮；
- 点药丸空白处或 **Ctrl+L** → 切到完整路径编辑（等宽字体），Enter 提交
  （沿用 `submitAddress` 的万能分派：网址 / 绝对路径 / 搜索词），
  Esc / 失焦取消；
- 取消/换目录时 `pathInput` 同步回 `currentPath`。

**为什么删掉整行路径输入框**：旧布局第一行是可编辑路径框、第二行是
面包屑，同一地址显示两遍（与 TitleBar 注释里的既有纪律一致：两处显示
同一串地址就是重复）。工具区高度从两行 ≈80px 降到一行 ≈40px。

**输入框常驻挂载**（编辑态之外 `display:none`）：AI 自控面
（`viewerControl.submitPathBar`）靠 `.path-input` 类名 + form submit
驱动 `set_path` 动作，不能只在编辑态渲染。`scrapeState` 的
`currentPath` 同时改读药丸上的 `data-path` 属性（旧读法拼
`.breadcrumb-bar` 的 textContent，各段连成一串、没有分隔符）。

### 2. 深路径：中段折叠 + 「…」展开

保留首段（盘符）+ 尾 N 段，装不下的中段收成「…」按钮，点击弹出被
折叠段列表（复用 `ContextMenu`，点段即跳）。收敛靠
`useLayoutEffect` 逐段回退测量（绘制前收敛，用户看不到中间态）；
换目录或药丸变宽（ResizeObserver）时回到全显再重新收敛。旧实现单段
180px 截断、整行 overflow:hidden 直接把搜索框挤出窗口，没有整行级折叠。

### 3. 右侧开关组：宽窗平铺（A），窄窗收进「⋯」（B）

- 常规宽度：隐藏文件 / AI / 主题三按钮平铺；**主题按钮改纯图标**
  （显示器/日/月图标本身表意，文字项「视图」菜单里已有，省 ~70px）。
- 窗口 ≤820px（`matchMedia`）：整组收进「⋯」，弹出菜单与「视图」菜单
  同一组开关（隐藏文件 / AI 栏 / 主题三选一），复用 `ContextMenu`。
- 搜索框 240→200px，与药丸同住一行；`searchNote`（全盘索引/当前目录
  标签）跟在搜索框右侧，语义不变。

### 4. 浮层让位

「⋯」与「…」两个弹出菜单计入 `floatingChromeOpen`——弹出时网页子
webview（独立 HWND，盖在 DOM 之上）照旧 hide，收起后 show。

## Alternatives considered

- **保留两行、只去重**（删面包屑或删输入框）：删面包屑丢掉逐级回跳；
  删输入框丢掉「粘个路径直达」。药丸双形态两者兼得，代价只是一次
  点击切换——Windows 资源管理器验证过的交互。
- **输入框常显 + 面包屑按需**：仍是两处地址，重复没消除。
- **右侧三项全部只留在「视图」菜单**：少一次点击都嫌多的场景没有，
  常用开关（隐藏文件）值得常驻位；窄窗时才退到 ⋯/菜单这条退路。
- **CSS 单行折叠（各段 flex 收缩各自省略）**：所有段一起压扁，不是
  「保首尾、折叠中段」，深路径下当前目录反而被挤没；测量式折叠才对。

## Consequences

- 工具区省一行高度（≈40px），地址只显示一遍；
- 旧 `.breadcrumb-bar` / `.path-form` 样式与 JSX 删除；`.toolbar-spacer`
  保留（图片/文档/表格/签名板编辑器的工具条共用这条规则）；
- `onPathSubmit` 拆出 `submitAddress(value)`（表单提交与编辑态共用）；
  AI 自控面的 `set_path` / `pathInput` 上报路径不变（类名与 form 结构
  原样保留）；
- 新增 Ctrl+L 全局快捷键（输入框内也生效——地址栏是全局目的地）；
- 深路径折叠引入测量-收敛循环（段数上限内必然收敛，无死循环风险）。
