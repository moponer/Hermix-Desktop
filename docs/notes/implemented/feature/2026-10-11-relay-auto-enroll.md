# Decision Note: 电脑侧 relay 凭据自动签发（enroll-node）

Status: implemented — 2026-10-11

## Decision

桌面端首次接入 relay 不再需要用户登服务器敲 `relayctl add-node` 再把明文凭据抄回界面。启动时（及每次主动配对前）若本机没有 `hrel_*` 凭据，桌面端把**自己的 E2EE 公钥** POST 给 relay 的新端点 `POST /api/relay/enroll-node`；relay 从公钥推导 node_id（与 `relay_settings::derive_node_id` 同算法，跨语言固定向量钉死）、签发 node 凭据并一次性下发。桌面端校验应答中的 node_id 与本机推导一致后落盘（DPAPI）并直接连接。

- 推导在 relay 侧做，**不接受客户端自报 node_id**——路由归属不能由请求方指定。
- **先到先得 + 409**：同一 node_id 只自动签发一次；重复请求拒绝。
- **总量闸门**：未撤销 node 凭据数上限 512，匿名端点必须有界。
- 自动签发失败（旧版 relay 无此端点 / 网络不通 / 409）不阻塞启动：回落到原有的人工路径（界面 `relayctl add-node` 指引 + 手填凭据），错误原文进 `relay_last_error` 与配对 428 文案。

## Alternatives considered

| 方案 | 为什么不 |
| --- | --- |
| 保持手动 relayctl（现状） | 「零安装」应用不该有人工登记环节；每台新电脑都要登一次服务器，用户此前已明确否决。 |
| 开放自报 node_id 的注册 | 任何人可凭空认领任意身份位：抢注未来某台电脑的 node_id、或刷任意 id 占库。 |
| enroll 时做私钥持有证明（PoP 签名） | 防的是「见过二维码（公钥）的攻击者抢注」——要求攻击者在真电脑首次 enroll 前就拿到公钥，窗口极窄；为此给静态 E2EE 身份加签名能力扩大加密面，不值。409 先到先得已把事后补签占槽关掉。 |
| 凭据丢失时允许同 node_id 重签（幂等） | 持公钥的攻击者可在真电脑离线时补签一条凭据占槽（真电脑重连即 4003 冲突）。重装电脑走 relayctl 重签，代价可接受。 |

## Consequences

- **得到**：新装桌面端 → 启动即连上官方 relay，手机扫码配对全链路零人工；自建 relay 升级到带此端点的版本后同样受益。
- **得到**：node_id 与 E2EE 身份在 relay 侧强绑定（公钥推导），配对码里的 `server_id` 天然对得上。
- **代价**：匿名端点新增一条滥用面——由「先到先得 + 409 + 512 上限 + 审计行」压到有界；relay 侧凭据表会积累未清理的登记行（与 issue-phone 未用行同一待清事项）。
- **代价**：同一身份只有一次自动签发机会，分三种场景——
  - **全新环境初次安装**（新盘 / 清 profile）：新身份 → 新 node_id → relay 无记录，enroll 直接成功。这是本决策的主场景，零人工。
  - **仅凭据丢失、身份完好**（relay.json 被删 / 换用户目录）：同 node_id 再 enroll 被 409 挡住，须登服务器 `relayctl revoke` 旧行后重签——这是关掉「凭据可匿名重取」口子的直接代价。
  - **身份文件解不开**（还原备份 / 搬盘 / 重建 Windows 账户，DPAPI 主密钥丢失）：E2EE 身份加载就失败（存量行为，非本决策引入；配对与手机会话此时本已瘫痪），enroll 在本地报「读取本机 E2EE 身份失败」，轮不到 relay。恢复走**自服务重置入口**（同日实现，见下）：界面「手机端 → 中转连接」的「重置本机身份…」→ `POST /api/relay/reset-identity`（仅 Local）删 `identity.json` 与 `relay_phones.json`、重写 `relay.json`（尽量抢救自建地址）→ 重新拉起出站连接任务 → 新身份自动签发直连。设备注册表刻意不动，旧设备照常可撤销或重新扫码。身份**不能**静默重生成——换钥必须显式，代价是全部手机重新扫码配对。
- 旧版 relay（无 enroll-node）行为不变：自动签发失败回落人工路径。
