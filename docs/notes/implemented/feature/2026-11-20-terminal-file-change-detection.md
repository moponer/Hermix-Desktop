# Decision Note: 终端改文件也进「已编辑 N 个文件」卡片（工作区差分）

Status: implemented — terminal 命令的文件副作用由命令前后工作区快照差分补成 `file_change` 事件，与结构化写工具同权。

## Decision

聊天尾部的「已编辑 N 个文件」卡片的**唯一数据源**是 `file_change` 时间线事件。此前只有结构化写工具
（`write_file` / `patch` / `edit_file`）会发这个事件——因为 `extract_file_change` 读的是工具**入参**。
模型经 `terminal`（`Set-Content` / `Out-File` / 重定向 / 脚本生成）改文件时，入参是一条命令，没有任何
结构化路径可解析，于是这类编辑**整个不可见**：卡片不出现，改动落在用户看不见的地方。

现在的实现分三层：

1. **纪律层**（`directions.rs::TOOL_USAGE_GUIDANCE`）：明令文件编辑禁走 shell，并给出四条理由（用户看不见
   改动 / 编辑不可验证 / 编码与换行会烂 / 审查路径被绕过）。这是**首选**防线——让模型一开始就不这么干。
2. **差分层**（`agent_loop/workspace_diff.rs`）：纪律是概率不是保证，所以兜底。含 shell 族调用的批次的
   命令前后各扫一次工作区，按 `mtime+size` 差分出 created / modified / deleted；`modified` 用命令前后的
   真实内容做**行级真 diff**（不是拿两次总行数冒充增删）。
3. **事件层**：差分结果走与结构化写工具**同一条** `file_change` 回调线路，并携带权威 `added`/`removed`。
   前端 `extractFileChanges` 优先用事件计数，缺失才回落到旧的入参估算；`FileChangeSummary` 的 tooltip
   按来源分两档说实话（真 diff / 估算下界）。

顺带修正：`extract_file_change` 原先不认 `edit_file`（`patch` 的别名），该流的文件变更事件整片缺失——
现已认全三个写工具名。

## Alternatives considered

- **只加纪律、不做差分**：纪律是概率不是保证。模型换一批工具、换个措辞就会绕过；绕过时改动仍然
  不可见，而这正是要消灭的故障模式。纪律与差分是「首选」与「兜底」的关系，不能互相替代。
- **解析 terminal 出参文本找文件路径**：即用正则从不稳定的命令输出里猜「改了什么」。同一件事有无数种
  输出形态（`Set-Content` 静默无输出、`git` 打印 stat、脚本自述），且输出可被命令任意控制——用文本猜
  等于让被观测者自己报告观测结果。差分只看**磁盘这个事实源**。
- **对整棵工作区做内容哈希快照**：正确但代价不成比例。一份中型仓库全量哈希是秒级 IO，而每个 shell 批次
  都要付一次。`mtime+size` 是 `git status` 同款假设（工具改文件必动 mtime），足够且便宜。
- **把计数塞进 `file_summary` 文本**：避免改 `ExecutionTimelineEvent` 结构，但把结构化数字降级成
  需解析、随语言漂移的字符串。事件本来就该携带权威计数——两个 `Option<u32>` 字段是正确的成本。
- **在前端用 tool_start 入参估算 terminal 的增删行数**：入参是命令字符串，估不出行数；硬估就是编造。

## Consequences

- **成本**：每个含 shell 调用的批次多两次工作区扫描。已设**四重**边界：跳过重目录
  （`node_modules` / `target` / `.git` / `dist` … 与隐藏目录）、文件数上限 4000（超出即整份差分放弃，
  宁缺毋滥）、单文件内容捕获上限 64 KB、**每次快照内容总量上限 8 MB**（超预算的文件仍记 stat——
  仍能报「变了」，只是不给行数）。最后一条把 IO 成本钉在上限内，而不是随仓库大小线性漂移
  （4000 × 64 KB 全读是 256 MB，不可接受）。纯读工具批次零成本。
- **假设**：`mtime+size` 未变即视为未改。时钟精度极粗的文件系统（如 FAT 2 秒粒度）在极端快速写入下
  可能漏判一次修改。这是与 `git status` 相同的取舍，不额外加哈希。
- **路径口径**：差分路径**相对工作区、正斜杠分隔**，与前端按 `/` 归一的逻辑同形；Windows 反斜杠不再
  泄漏到事件里。
- **去重**：同一批次里已被 `write_file`/`patch`/`edit_file` 覆盖的文件不再由差分重复上报（模型常见做法是
  terminal 生成 + patch 微调）。
- **不做**：不还原被删文件的内容，不做逐行 annotate（卡片只报路径、类型、行数）。需要看具体改动仍然走
  右栏预览与 `git diff`。
