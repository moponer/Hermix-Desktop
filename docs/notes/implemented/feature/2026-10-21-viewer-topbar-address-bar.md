# Decision Note: viewer 顶栏改浏览器式地址栏（标题栏只放窗口身份）

Status: implemented — 自绘标题栏只保留应用名 / 菜单 / 窗口按钮；纯净模式顶栏是一条三栏网格：左网页导航、中地址栏（居中、主机/文件名加重、路径压暗、点击复制）、右动作按钮。同一串文件名或网址在界面上只出现一次。

关联：[viewer 自绘右键菜单 + 自绘窗口标题栏](../feature/2026-10-20-viewer-context-menu-and-custom-titlebar.md)（本文取代其 Decision 6 中「标题栏 = 应用名 + 当前文件/目录」那半句）、[viewer 顶部路径栏万能输入框](../feature/2026-10-20-viewer-pathbar-universal-input-and-global-search.md)

## Decision

**1. 标题栏与地址栏分工，一个事实只出现一次。**

- 标题栏（`TitleBar.tsx`）= **窗口身份**：品牌图标 + 应用名 + 菜单（文件/视图/工具/帮助）+ 最小化/最大化/关闭。不再显示当前文件或网址。
- 顶栏（`.pure-bar`）= **位置**：地址栏 + 动作。纯净模式没有别的区域显示文件，这里就是唯一入口。
- 任务栏 / Alt+Tab 需要的文档名走 `getCurrentWindow().setTitle("名字 — Hermix 文件查看器")`，由 App 在模式/文件变化时维护——自绘标题栏不承载它。

改前实测：同一个网址在标题栏与顶栏各出现一遍，用户看到两遍却分不清哪一处该看。

**2. 纯净模式顶栏用三栏网格，地址栏真的居中。**

`grid-template-columns: minmax(0, 1fr) minmax(220px, 680px) minmax(0, 1fr)`：中列有上限、两侧等宽，左导航（仅网页标签有）与右动作各占一格。用 flex 的话右侧两个文字按钮会把地址栏顶得偏左，"中间地址栏"名不副实。这一行的控件统一 30px（`.pure-bar` 内覆盖 `--ctl-h`），地址栏是视觉主角。

**3. 地址分两段显示，主标识优先保住。**

- 网页：主机加重（`--font-weight-medium`）+ 路径/查询/锚点压暗（`--text-secondary`）。
- 文件：文件名加重 + 目录压暗（目录带尾分隔符）。
- 窄窗口里先省略次要那段（`.loc-tail` 可压缩），主标识最多吃 55% 宽度。

**4. 地址是只读的，所以整颗药丸就是「复制地址」。**

点击/回车 = 复制完整地址到剪贴板 + 轻提示（`网址已复制` / `路径已复制`）；悬停或键盘聚焦时右侧浮出复制图标（渐进披露，不让常驻图标成为噪音）。完整地址同时放在 `title` 里。

**5. 网页导航上移，WebPane 在纯净模式不再自带工具条。**

纯净模式下网页标签的后退/前进/刷新改成顶栏左侧三个按钮（同一条 `web_exec` 通道）；`WebPane` 新增 `chrome` 参数，纯净模式传 `false` 关掉它自己那条「导航 + 网址 + 系统浏览器」。否则同一网址出现两遍、两个「用系统打开」。

`web-navigated` 事件在 App 里也监听一次：页面内点链接跳走后，地址栏显示的是**当前**地址；「系统打开」打开的也是当前页，不是打开标签时那一页。

**6. 右侧按钮的图标尺寸与样式统一。**

- 动作按钮（系统打开 / 重量模式）图标 14px（`.icon-sm`），与 13px 文字同重；模式切换图标从 `HardDrive`（读作"磁盘"）换成 `PanelsTopLeft`（读作"多栏布局"）。
- 纯图标按钮补 `.tb-icon`：方形、左右内边距归零（`.tb-btn` 的 8px 是给「图标 + 文字」留的，只有图标时按钮成了胖矩形、图标看着不在正中）。
- 窗口按钮 46×28（Windows 11 量级），图标 15/13/15px；关闭按钮 hover 用红底白叉（`--danger` + `--text-on-accent`），不再只是浅红字。

**7. 纯净模式不再出现第二条文件名。**

`PreviewHost` 新增 `showName`，纯净模式传 `false`：顶栏地址栏已经显示文件名，预览工具条再写一遍就是隔 30px 的第二次。标签条那一行整行隐藏（`.preview.is-pure .tabbar-wrap`）——只藏 `.tabbar` 会剩一条灰条上挂着一个失去对象的列表收起按钮。

## Alternatives considered

1. **保留标题栏副标题，只调字号/间距** —— 拒绝：重复本身是主诉，调样式不解决"看到两遍不知道信哪一处"。
2. **地址栏做成可编辑输入框（浏览器 Ctrl+L 的语义）** —— 本轮拒绝：纯净模式是"双击就看"，没有导航语义；可编辑框必须同时处理"网址 / 路径 / 搜索词"三种输入的分派，而那正是重量模式路径栏已经承担的职责。两个入口、两套心智模型，代价大于收益。
3. **地址栏左对齐（Chrome 式 flex 布局）** —— 拒绝：右侧动作按钮一宽就把地址栏挤得偏左，用户要的是"中间"。
4. **点击地址栏只选中文本，复制交给 Ctrl+C** —— 拒绝：只读地址最常做的动作就是复制，选中后再补一次按键是多余的一步；复制同时给 toast，动作有回执。
5. **顶栏地址栏与 WebPane 工具条并存** —— 拒绝：同一网址、同一个"用系统打开"各出现两次，等于把刚消掉的重复换了个位置。
6. **地址栏常驻复制图标** —— 拒绝：安静时它是一个每一屏都在的噪音；悬停/聚焦浮出足够被发现。
7. **把网页导航做成隐藏式（只在悬停时出现）** —— 拒绝：导航是高频动作，隐藏会让"能不能后退"变成猜测。

## Consequences

- **标题栏不再显示当前文件**：靠 `setTitle` 的窗口标题兜底（任务栏 / Alt+Tab 可见）。若将来有逻辑想从标题栏读文档名，那里已经没有了。
- **纯净模式的地址栏是只读的**：想改地址要切重量模式（路径栏是万能输入框），或直接用「系统打开」交给浏览器。
- **导航按钮依赖 `web_exec` 操作当前子 webview**：没有网页标签时左侧整格留空（网格保证地址栏仍居中），按钮不渲染。
- **`chrome` / `showName` 两个参数是模式差异的唯一出口**：WebPane 与 PreviewHost 自身不知道自己处于哪种模式，模式判断集中在 App。
- **窗口按钮尺寸只影响自绘标题栏**：`decorations: false` 下的边缘缩放仍由 Rust 侧补 `WS_THICKFRAME`，本次未触碰。
- **`system-panel.css` 里对 `.tb-brand` / `.tb-spacer` 的覆盖已删除**：布局规则回归 `styles.css` 一处，避免两个文件各写一半。
