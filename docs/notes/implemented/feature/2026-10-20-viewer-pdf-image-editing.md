# Decision Note: 查看器的 PDF / 图片编辑能力加强 —— 文档级操作走 pdf-lib，内容流手术留在 lopdf

Status: implemented — PDF 新增合并 / 裁剪 / 水印 / 页码 / 文档信息五项文档级操作；图片新增黑白二值化与「压到指定体积」。

## Decision

**PDF 分成两层内核，各管各的，产物各自是新文件：**

- **内容流层（Rust，lopdf 0.34）** —— 页级增删排旋转、插空白页、文本层整串
  替换、图片转 PDF。这层要动 PDF 的内容流（`Tj` 算子的字节），lopdf 已经在
  工作区 Cargo.lock 里，不新增编译单元。
- **文档级层（前端，pdf-lib 1.17，懒加载）** —— **合并多份 PDF**、页面裁剪
  （CropBox）、文字水印、页码、文档信息（标题/作者/主题/关键词）。

为什么文档级不继续在 lopdf 里手搓：合并多文件要深拷贝并重编号整棵对象图
（页 → 资源 → 字体/图片，还要把 /Parent 重新挂到新页树上），水印与页码要给
页面挂字体资源并拼内容流——这些是**二进制级别**的活，pdf-lib 有成熟实现，
自己写等于把几百行高风险代码塞进产品。pdf-lib 是 MIT，**只在用户真的打开
「文档工具」时才动态 import**，不进首屏包。

**中文字水印**走「浏览器画布 → PNG → 贴进页面」：pdf-lib 的标准 14 号字只有
拉丁字形，中文会变成空白。ASCII 水印则用矢量字体（体积小、任意缩放清晰），
两者按文字内容自动切换。

**图片侧新增两项：**
- **黑白二值化**（`ImageOp::Binarize`）——按 Rec.601 亮度过阈值，与灰度的
  区别是只留黑白两档，扫描件去灰底用。前后端各一份实现，公式钉死
  （`(77R + 150G + 29B) >> 8`），预览与导出同序。
- **压到指定体积**（`image_compress_to`）——给目标 KB，二分找**仍满足上限的
  最大 JPEG 质量**。PNG 是无损的压不动，所以产物一律 JPEG（后缀强制跟内容
  一致）。目标不可达时如实报错并附最低质量下的实际体积，**不静默产出超标
  文件**。压缩作用在**用户改完的图**上（op 链先跑），不是原图。

顺带补了「旋转 180°」按钮（内核早就支持，只是没露出来）。

## Alternatives considered

- **用 Univer 做表格 / WordCraft、GridCraft 做 Office 内嵌** —— 调研结论见
  [2026-10-20-viewer-office-editing-inplace.md](2026-10-20-viewer-office-editing-inplace.md)。
  本轮不内嵌。
- **PDF 加密（打开密码）** —— **没做**。pdf-lib 1.17 与 lopdf 0.34 都只能
  **读**加密 PDF，不能写：写加密要自己实现 RC4/AES 的密钥派生与逐对象加密。
  与其做一个「以为加密了其实没加密」的假象，不如先不做。
- **图片水印** —— **没做**。`image` 0.25 没有内置字体（`draw` 模块已移除），
  要画字得引字体栅格化依赖或走 Win32 GDI（自己造 DIB + 选字体 + TextOut）。
  现有的**文字图层**已经能加字（前端画、导出时整张合成交给 Rust），能力上
  够用；真要做「平铺半透明水印」再单独评估。
- **批量转换/重命名的 UI** —— 内核（`image_batch`）早就有，前端没接。本轮
  没接（界面工作量大于内核），留作后续。
- **把 pdf-lib 换成 Rust 侧实现** —— 拒绝：等于自研 PDF 二进制手术，风险与
  工作量都不成比例，且违背「少依赖、快」的准则。

## Consequences

- 查看器新增一个运行时依赖（pdf-lib 1.17，MIT，动态加载，不进首屏包）。
  `pnpm-lock.yaml` 与 `apps/viewer/package.json` 同步更新。
- **PDF 两层内核不交叉**：同一份文档里「删页」与「加水印」不能一次导出，
  要分两次（先页级导出，再用文档工具处理导出的那份）。跨 IPC 传整份 PDF
  字节的代价本轮不值得。UI 上两处入口分区呈现，语义写清。
- PDF 文档级操作**只改文档层**：不动内容流，所以扫描件里的文字层、页眉页脚
  原样保留；反过来，内容流手术（文本替换）也不碰页面结构。
- 图片二值化是不可逆的信息丢弃（层次全没了），滑杆归位到 128 即撤销该 op。
- 压到体积会**转成 JPEG**：透明通道丢失、原图色彩模式变化。UI 提示里写明
  产物是 JPEG。
