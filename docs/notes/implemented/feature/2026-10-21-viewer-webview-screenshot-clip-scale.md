# Decision Note: `webview_screenshot` 加 `clip` + `scale` —— 让 agent 看得清页面小字

Status: implemented — 2026-10-21 真机验证：超星 1.3 测验 6 题全部由裁剪 2 倍截图读出，
1.3 最终成绩 100 分

## Decision

`webview_screenshot` 增加两个**可选**参数：

- `clip = {x, y, width, height}`：裁剪区域，单位是**顶层文档 CSS 像素**
  （与 CDP `Page.captureScreenshot.clip` 语义一致 —— 相对**文档**左上角，
  **不受滚动影响**）；
- `scale`：放大倍数（常用 2）。裁剪 + 放大 = 只把要看的那一小块以 2 倍像素喂给模型。

不给 `clip` 时行为不变（整视口截图）。

**缩略图仍压到最长边 1024**（`SHOT_MAX_WIDTH`）—— 这次改的不是「把整图放大」，
而是「**先裁小、再放大**」，所以进上下文的图片反而更小。

## 为什么

整视口截图会被压到 1024 宽。超星测验题正文是 14px → 压完约 7px，**认不出字**。
而「读出题面」是刷课闭环的必需环节：超星用 `font-cxsecret` 把正文换成生僻字
（`系统是由处于一定环懌中的…`），**DOM 读不出、像素是正常的** → 只能看图。

物理约束：模型的视觉输入按图像面积计费。1920×896 整图 vs 814×370 裁剪块
（放大 2 倍后 1628×740，但内部仍是同一块内容）—— 后者既清晰又只占一小块上下文。

## Alternatives considered

- **把 `SHOT_MAX_WIDTH` 从 1024 提到 1920**：整图进上下文，按面积计费直接是
  上下文炸弹，且**没有放大效果**——1920 宽的图里 14px 字还是 14px 像素。
  否决。
- **用 CSS `zoom` 放大页面再截图**：会**重排布局**——超星选项从「一行四个」
  变成「一行一个」，每题要截 3~4 张；而且点击坐标全部失效。
  否决（实测过，2 倍 zoom 下选项竖排）。
- **把原分辨率 PNG 直接塞给模型**（不压到 1024）：同「提高上限」，上下文炸弹。
  否决。
- **接一个 OCR 工具**：多一个依赖、多一层误差，且模型本身有原生视觉。
  否决。

## Consequences

- agent 读页面小字（试题、表格单元格、状态徽标）从「做不到」变成「一步到位」，
  且不增加上下文占用。
- **主要坑**：`clip` 是**文档坐标**不是视口坐标。页面滚动后必须把
  `scrollY` 累加进去，否则裁到一片空白（实测踩过：裁剪区全白）。
  量元素位置要沿 `frameElement` 链把每层 iframe 的偏移与滚动量都加起来。
  这条已写进内置 skill `browser-automation` §3.1。
- 原分辨率 PNG 仍然全量落盘（`~/.hermix/browser-shots/`），用户可直接打开。
- `clip` / `scale` 是**可选参数**，不传即保持旧行为 —— 已有调用方零改动。

## Reintroduction conditions

（feature 类不要求本节；如未来要撤掉 `clip`，条件是出现一种不依赖像素、
又能直接拿到页面文本的通用手段 —— 例如站点自己提供无混淆的文本接口。）
