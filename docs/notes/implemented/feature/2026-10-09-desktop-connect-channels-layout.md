# Decision Note: 桌面端「连接渠道」改主从布局

Status: implemented — 2026-10-09

## Decision

`设置 → 设备` 里的三个连接渠道（QQ 机器人 / 企业微信机器人 / 手机端）从
**竖着堆三块卡片**改成**左栏选、右栏配**的主从布局。

```
┌────────────────┬──────────────────────────────────────────┐
│ [图标] QQ机器人  │  [大图标] QQ 机器人                       │
│        通道已连接│  QQ 开放平台机器人 · 只处理私聊           │
├────────────────┤  ┌──────────────────────────────────────┐ │
│ [图标] 企业微信  │  │ 已绑定 8f2a… ● 通道已连接  [配对码][解绑][重新扫码] │ │
│        未绑定    │  └──────────────────────────────────────┘ │
├────────────────┤  状态条 / 排查提示 / 二维码 / 配对码面板    │
│ [图标] 手机端    │                                          │
│        配对码就绪│                                          │
└────────────────┴──────────────────────────────────────────┘
```

### 为什么竖排是错的

三个渠道是**同一件事的三个选项**，不是三个步骤。竖排把「三选一」画成了
「一连串」，于是：

1. 一屏放不下两条，扫一遍要滚动；
2. **「我现在配的是哪个渠道」在竖排里没有位置**——三块长得一样，只能靠读标题
   才知道自己在看哪条；
3. 「配对与授权」又是一块独立卡片，但它内容与渠道一一对应（`makePairCode(platform)`
   本来就按平台生成），挂在全局反而**丢掉了「这枚码发给哪个机器人」这个前提**。

### 具体改动

- `ImChannelsCard` 重写为 `连接渠道` 主从组件，左栏 232px 选择器
  （图标 + 名称 + 状态点，扫一眼知道哪个通了）、右栏当前渠道的全部配置。
  窄窗口下 `md:grid-cols-[232px_1fr]` 自动折成上下，不挤压。
- **配对码从全局卡挪进各渠道自身**，只在 `pairCode.platform === 当前渠道` 时显示。
- **手机端渠道并入**：原先在 `DevicesTab` 里单独一块的配对二维码与 6 位码，
  跟着「手机端」这个渠道走。选到该渠道才生成二维码，不选不做这份无用功。
- `DevicesTab` 只保留**已配对设备**全局表（IM 账号 `qq:<openid>` 也在其中，
  是跨渠道的），不再重复持有二维码逻辑。
- 删掉顶部两张「第 1 步 / 第 2 步」引导卡——步骤框架与「三选一」的信息架构矛盾。

### 图标

三个渠道各用一个可辨识的 lucide 图标 + 品牌色徽标，替掉原来「Q」「微」的
字母圆标（那种写法是为了避免画来路不明的 logo，但结果只传达了「有一个圆圈」）：

| 渠道 | 图标 | 色 |
|---|---|---|
| QQ 机器人 | `MessageCircle` | `--color-brand-qq` |
| 企业微信机器人 | `Building2` | `--color-brand-wecom` |
| 手机端 | `Smartphone` | `--color-accent` |

左栏 32px 徽标、右栏标题 40px 徽标——右栏的大图标是为了「不留白」：进到某一
个渠道时，右上角有一个足够重的视觉锚点，页面不会因为只有几行字而显得空。

### 层次不靠描边

新组件内**没有任何 border**。卡片用 `bg-bg-card`，控件用 `bg-bg-tertiary`，
左栏容器用 `bg-bg-secondary`，选中项靠底色差 + 轻阴影，与手机端同一套规则。

> ⚠️ 只在这一块执行。桌面端设置页其余部分（以及整个桌面端）目前仍大量使用
> `border-border-primary`，全量统一是一次独立的、范围明确的改造，未在本次做。

## Alternatives considered

| 方案 | 否决理由 |
|---|---|
| 底部 Tab 切换三个渠道 | 设置页本身已有左侧导航，再加一层 tab 是两层导航套嵌；且渠道数会变（将来加飞书），tab 横向放不下。 |
| Accordion 手风琴竖排 | 仍是竖排，只是省了高度；「在配哪一条」的问题没解决——展开的那条要靠位置记忆。 |
| 每渠道一个独立设置页（左侧设置导航加子项） | 三级导航过深；而且渠道之间要横向对比状态时要多点几次。 |
| 保留竖排，只把卡片内的嵌套层级拍平 | 「在配哪个渠道」的问题依然存在，治的是乱不是根本。 |
| 保留全局「配对与授权」卡 | 配对码是按平台生成的（`makePairCode(platform)`），全局呈现会丢失归属。 |

## Consequences

- **得到**：渠道状态一屏可见、配置一处集中；配对码与其归属渠道不再分离。
- **得到**：二维码生成从「每次进设置页就生成」变成「首次切到手机端时生成」，
  省掉一次无谓的 `/api/pairing/sessions` 调用。
- **行为变化**：手机端二维码不再在进入设置页时就备好，必须先选中「手机端」
  渠道。这是主从布局的必然结果，也是合理的（不选就不需要）。
- **边界**：`ImChannelsCard.tsx` 与 `DevicesTab.tsx` 不在在线更新并行开发的
  改动面内（其改动集中在 `updater.rs` / `UpdatePanel.tsx` / `useUpdater.ts` /
  `Sidebar.tsx` / `ChatView.tsx` / `UserMenuPopover.tsx` / `relay/src/server.js`），
  无冲突。
- **回滚**：`git checkout -- apps/desktop-tauri/src/components/settings/`。
