# Decision Note: 对话正文降噪 —— 文件类型图标改淡染形态，行内 code 不再加粗

Status: implemented — 正文路径前的文件图标改 `FileTypeIcon` 的 soft 形态（淡染底 + 文字色字形）；行内 code 高亮去字重；2026-10-26 第二轮：系统提示加「强调预算」、文件名形态统一、同一文件名只首个带图标

## Decision

用户实机反馈："对话中 LLM 输出的图标……包括一部分重点加粗带背景色的特殊
词汇，看起来界面有点乱，要优化的美观一点"。

拆开看是**两处噪声**，一起处理。

### 1. 文件类型图标：实色方块 → soft 形态

正文的路径链接前面顶着一个 16px 的文件类型图标（`FileTypeIcon`）：**品牌
实色方块 + 白色粗体字母**（PDF 红 / TS 蓝 / JS 黄，字母 fontWeight 700）。
这正是用户说的"重点加粗带背景色的特殊词汇" —— 一段话五个文件就是五块彩色
积木，眼睛读的是色块而不是句子。

`FileTypeIcon` 新增 `variant`：

- `"solid"`（默认，列表行 / 文件管理器 / 预览 tab 不变）—— 品牌实底 + 白字；
- `"soft"`（**正文用**）—— 同色相淡染底（不透明度 22% → 14%）+
  字形走 `currentColor`（跟正文色）。

为什么字形必须用文字色：品牌色表里有一半是浅色（JS 黄、SH 绿、ENV 黄），
白字压在实底上根本读不出（这也是原实现要加一圈黑色描边的原因）。soft 形态
把底色降到淡染、字形交给文字色之后，**描边也不需要了** —— 纸面对比度由正文
的 `--color-text-primary` 保证。

结论：色相还在（扫一眼知道是什么类型），重量没了。

### 2. 行内 code：加粗去掉

行内 code（`` `null` ``）是"底色药丸 + 语法高亮"，而 `codeHighlight.ts` 的
调色板里 keyword / function / boolean / constant 都是 `fontWeight: 600`。
底色已经占了"这是代码"的重音，再叠一层字重就是两个重音互相抢。

`highlightToReact` 新增 `inline` 参数：行内 code 一律去字重、保留颜色。
**代码块不受影响** —— 那里没有底色，字重是区分关键字的唯一手段。

### 3. 附带查清的一件事

实测（node 环境渲染 `<MarkdownBody content="`null`" />`）：**行内 code 今天
根本没有语法高亮** —— `MarkdownBody` 里的 `isProp` 分支要靠 hast 上的
`prop="true"` 标记，而 satteri 不给行内 code 设这个属性，于是那个分支是
死代码，行内 code 渲染成纯文本药丸。

所以第 2 条是**预防性**的：哪天 satteri（或别的解析器）开始设 `prop`，行内
code 会亮起来，但不会同时变粗。死代码本身保留（它还兼作"行内 code 上色"
的开关位），不删。

### 4. 工作台画布底色改用 `--color-bg-base`

同一批反馈里还有一条："工作台命名后还没开发完，背景色一直是白色的网页
背景"。根因不在 iframe：`.wb-canvas` 铺的是 `--color-bg-primary`
（浅色主题 = 纯白 `#ffffff`），而未开发的工作台没有自己的背景规则，
于是整块画布就是一张白纸。

改铺 `--color-bg-base`（浅色 `#f5f5f5` / 暗色 `#1f1f1f`）：画布与右侧
对话的纸白拉开一档，工作台读作"应用里的一块画布"而不是"没加载出来的
网页"。工作台自己的代码要整页底色仍然照旧写 body/html 的 background
（iframe 文档 html 是透明的，body 的背景按 CSS 规范就是画布底）。

### 5. 第二轮（2026-10-26）：强调预算

用户再次反馈「LLM 的输出看起来有点乱，好像很多的文件名、很多的加重」。拆开
看，**单件样式已经不是瓶颈**（芯片半透明不加粗、图标 soft 化都已落地），
真正的瓶颈是**密度**——一段正文里同时存在四种重音：`**加粗**`（600 字重）、
`` `反引号芯片` ``（等宽 + 底色药丸）、裸文件名链接（等宽 + 下划线 + 图标）、
反引号里的文件名（**药丸底里再嵌链接**的叠加态）。

密度由**系统提示**决定，不是渲染层：`directions.rs` 的 `format.short`（中文）
与 `THINKING_DISCIPLINE_GUIDANCE`（英文）原本都写着「**加粗关键词**」「use
`**bold**` for key terms」——无上限鼓励。两处同步改为**有预算**的表述：

- 加粗**每段至多一处**，只标记该段结论性关键词；
- 文件名 / 路径**不加粗**，且**写字面量、不带反引号**（界面会自动渲染成可点
  链接）；
- 反引号只包真实标识符、命令与路径值，不包普通名词。

### 6. 第二轮：文件名形态统一（消除叠加态）

此前同一个文件名会因 LLM 当场是否写反引号而长成**两种**样子：`` `App.tsx` ``
是「药丸底里再嵌下划线链接」，`App.tsx` 是「等宽 + 下划线 + 图标」。

改法：整枚行内代码恰好是一个路径时，**不套芯片，直接渲染成 PathLink**。
此后带不带反引号渲染完全一致；老消息里的反引号也立刻归一。

### 7. 第二轮：同一文件名只首个带图标

图标是行内最大的重音件（16px vs 正文 14px），而 LLM 爱在一段里反复提同一
文件。改为**一条消息内同一路径只有首次出现带文件类型图标**，后续退化为纯
链接（仍可点、`title` 仍给完整路径）。去重作用域 = 一条消息（`linkifyChildren`
新增可选参数 `iconSeen`，不传时作用域 = 本次调用）。

## Alternatives considered

- **把正文里的文件图标整个去掉** —— 试过并回退。去掉确实更安静，但代价是
  丢掉"扫一眼知道是什么类型"的能力，而正文里 `App.tsx` / `login.rs` 这类
  引用常常一屏好几个，类型线索有价值。soft 形态是同一个目标的另一条路：
  减重量、不减信息。

- **把图标改小（13px / 12px）** —— 否决。字母在 24 viewBox 里只有
  7.5–10.5px，13px 渲染出来约 5.7px，只剩一个认不出类型的色块 —— 更小
  换来的是更看不清。

- **图标改中性底 + 彩字（仓库的 `.cat-icon` 形态）** —— 否决。那套形态的
  前提是"字母是文字"，但这里的字母要跟品牌色绑（类型线索），而品牌色里
  有一半在浅色纸上过不了 4.5:1。soft 形态把"彩"放在**底色**上、字形交给
  文字色，绕开了这个矛盾。

- **行内 code 干脆不上色（纯文本药丸）** —— 否决。颜色让读者一眼看出哪一段
  是标识符/字符串，去掉是信息损失；要去掉的只是**字重**。

- **工作台画布改用一个自定义灰阶** —— 否决。现成的 `--color-bg-base`
  就是"内容之下的底面"这一档，且已随三套主题定义。

- **在渲染层给加粗限流**（每段超过 N 处就把多余的加粗降回普通文本）——
  否决。渲染层无从判断哪一处加粗是多余的、哪一处是真正的结论；改写 LLM
  输出的语义属于暗改内容，不该由展示层做。密度只能在**产生端**（系统提示）
  治。

- **把 strong 的字重从 600 降到 500** —— 否决。中文 500 与正文 400 的区分度
  太弱，加粗将失去「这是结论」的语义；且单件不重，问题是数量不是重量。

- **文件名形态统一改成「反引号内保留芯片，只去掉内嵌链接」** —— 否决。那样
  同一个文件名仍然是两种长相（芯片 / 链接），只是把叠加态的第三种修掉；统一
  要统一到**一种**。

- **重复文件名全部都不带图标** —— 否决。丢掉"扫一眼知道是什么类型"的线索
  （正文里 `App.tsx` / `login.rs` 一屏好几个，类型线索有价值）。只让首个带
  图标，重量付一次、信息不丢。

- **旁注轨道也一并在本篇里恢复** —— 否决（分工问题，不是效果问题）。轨道
  恢复撞上的是 G11 门禁的判据边界（什么算「结构描边」、什么算「功能性标记」），
  属于门禁策略；本篇只管正文降噪。轨道恢复的决策与画法见
  [2026-10-26 CSS 层描边门禁与功能性标记的画法](../process/2026-10-26-css-border-gate-and-functional-rails.md)。

## Reintroduction conditions

- **正文图标恢复实色形态** 的条件：出现"正文里密集出现文件引用、淡染方块
  仍显干扰"的实测反馈。恢复时应同时评估是否退回"只在最终答复开图标"的
  旧规则（`pathIcons` 默认关，思考块/工具结果不开）。

- **行内 code 恢复字重** 的条件：出现"必须一眼从正文里挑出关键字"的
  场景（例如正文密集讨论某段源码的语义）。恢复时应限定在"该段是源码
  引用"的上下文，而不是全局加回来。

- **放宽强调预算（加粗恢复到不限处）** 的条件：实测出现"结论性关键词淹没
  在普通加粗里、读者找不到重点"的反馈。放宽时优先改回「按段落只允许一处」，
  而不是取消限制。

- **恢复「文件名一律带反引号」** 的条件：无。这条已被形态统一取代 —— 反引号
  里的路径现在会被渲染成与字面量完全相同的 PathLink，带不带反引号不再影响
  观感。

- **重复文件名恢复每次都带图标** 的条件：出现"同一个文件在一条消息里出现
  多次，用户需要靠图标逐次确认类型"的实测反馈（当前形态下首次已给足线索，
  重复出现只补文字）。

## Consequences

- `FileTypeIcon`（共享包 `@hermix/preview`）多一个 `variant` prop，默认值
  `solid` —— **现有调用点行为不变**（列表行、文件管理器、预览 tab、
  设置页）。只有正文路径链接改成 `variant="soft"`。

- `MarkdownBody` 的 `pathIcons` prop 保留（默认关）：只有最终答复正文
  （`ToolCallBubble` 的 `kind === "text"` 步）开图标，思考块/工具结果/
  更新日志不开 —— 一段十几个路径全顶方块，正文会被切成拼贴画。

- `highlightToReact` 多一个 `inline` 参数（默认 false）。行内 code 仍是
  "药丸底色"，只是不会再出现加粗的字。

- 工作台画布在浅色主题下由纯白改为 `#f5f5f5`，与侧栏/卡片同一档；
  工作台代码自带的整页底色仍优先（html 透明 → body 背景就是画布底）。

- **`directions.rs` 两处系统提示文案同步改动**（`format.short` 中文 +
  `THINKING_DISCIPLINE_GUIDANCE` 英文）。**只对新会话生效**：密度变化来自
  LLM 的输出行为，历史消息不会被重写；而第 6 条的形态统一与第 7 条的图标
  去重是渲染层改动，**历史消息立即生效**。

- **`linkifyChildren` 多一个可选参数 `iconSeen`**（默认新建 `Set`，作用域 =
  本次调用）；调用方要跨段落去重就自己建一个传进来。`MarkdownBody` 的渲染器
  传的是**一条消息共享**的 Set（p / li / blockquote / callout 四处调用点）。

- **整枚行内代码是路径时不再包 `<code class="md-inline-code">`**，直接输出
  PathLink —— 少一层 DOM，也顺带让 `md-inline-code` 这个孤儿类名彻底没有
  使用者。

- **验证**：`cargo check -p hermix-agent` 通过；`cargo test -p hermix-agent
  --lib`（1188 passed / 0 failed）；`vitest` 的 MarkdownBody 两个文件
  （15 passed，含本轮新增 2 例）；`tsc --noEmit` exit 0；
  `check-design-guard` / `check-design-primitives` / `check-theme-tokens`
  / `impeccable detect` 均通过。
