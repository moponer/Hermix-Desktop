## 核心设计原则：把隐式 fail-open 变显式声明

`decide_pre_tool_dispatch` 当前在无审批通道时**静默 Allow**。该行为被 `layer4_no_approval_requester_falls_back_to_allow` 测试主动固化，注释自称 "graceful fallback"。问题不在于测试存在，而在于**调用方无法表达"我这条路径上危险工具应该被拒绝"**。

改法：新增 `ApprovalFallback` 枚举，作为**必填参数**传入决策函数。

```rust
pub enum ApprovalFallback {
    /// 无审批通道且危险 → Deny。用于网络可达路径（HTTP / 裸 WS）。
    Deny,
    /// 无审批通道且危险 → Allow。用于本地交互式终端（stdio/CLI）
    /// 与单元测试——这些调用方没有可被网络触发的攻击面。
    Allow,
}
```

调用方必须显式选择，编译器强制表态。默认不再存在。

| 调用方 | 位置 | 暴露面 | 选型 |
|---|---|---|---|
| 流式 WS | `ws.rs:740` | 局域网 | 已接审批器，不受影响 |
| 非流式 HTTP | `routes.rs:1465` | 局域网 | **Deny** |
| 裸文本 WS | `ws.rs:139` | 局域网（活 socket） | **Deny** |
| stdio 会话 | `stdio_session.rs:249` | 本地 stdin/stdout | **Allow** |
| 单元测试 | 各处 | 无 | **Allow** |

`Deny` 时返回可机读 reason，让 LLM 能改写而非静默失败。

## 逐项修复

### P0

**#1 审批 fail-open** — `local_agent_service.rs:1267,1318,2729`
引入 `ApprovalFallback`，三处 `else { return Allow }` 改为 `else { return fallback.resolve(...) }`。
同步改 `layer4_no_approval_requester_falls_back_to_allow` → 拆为两个测试（Deny 路径 + Allow 路径）。
风险：非流式 HTTP 上 Dangerous 工具将返回 Deny。这是**预期行为变更**——此前它们静默执行。

**#2 配对指纹未强制** — `pairing.rs:587 pair_page` / `:508` URL 组装
现状：指纹字段在 `QrPayload:369` 存在但未进 URL；`pairing.rs:726` 注释谎称"指纹核对在 /pair 页与桌面端之间进行"，而该页无此逻辑。
改法：把 `cert_fingerprint` 放进 `/pair?c=<code>&fp=<fingerprint>`，`pair_page` 回显指纹供用户肉眼比对，`complete_pairing` 要求客户端回传指纹并与本机 TLS 指纹比对，不符则拒发 device_token。同时修正 `:726` 的错误注释。

### P1 前端

**#3 ApprovalDrawer Enter 双触发** — `ApprovalDrawer.tsx:147-159`
`window` 级 keydown 把 Enter 劫持为 `act("once")`；焦点若在 Deny 按钮上，原生 click 触发 deny **同时** window 监听器触发 once——同一次按键既拒又允。
改法：keydown 监听挂在抽屉容器而非 `window`；`Enter` 仅在焦点不在任何 `<button>` 时生效（让原生 button 激活唯一地胜出）。危险动作不再绑定无条件 Enter。

**#4 澄清回复静默丢弃** — `useStreamParser.ts:736-737`
`if (!liveUnlisten) return;` 无日志、无 REST fallback，agent 卡在自己的超时上。
改法：与审批路径对齐，补 `tracing` 日志 + REST fallback（`App.tsx:1457` 已有同形实现）。

**#5 跨会话误杀流** — `chatStateReset.ts:87`
`deps.cancelStream()` 不传 sessionId，绕过 `useStreamChat.ts:778` 归属守卫。
改法：传 `activeSessionId`；`settle()`/`cancel()` 清槽条件统一为同一判据（消除 settle 只在 `keepSessionAlive` 为假时清、cancel 无条件清的不对称）。

### P2 后端健壮性

**#6 tool_executor panic 归因** — `tool_executor.rs:621-652`
panic 被正确捕获，但错误塞进**第一个空槽**，把 panic 消息归因到无关工具名。真实 panic 的槽留 `None`。
改法：用 `JoinSet::join_next_with_id` 拿到 task_id 映射到原 tool_call；无法映射时用独立占位而非猜测空槽。

**#7 sub_agent 超时后工具仍落盘** — `sub_agent_orchestrator.rs:812`
协作式 interrupt 只在 `llm_retry.rs:160` 被观测，工具执行路径无检查。
改法：工具执行循环内加 `check_interrupt()` 边界。

**#8 审批串行** — `tool_dispatch.rs:194`
for 循环逐个 `rx.await`，N 张卡 N 次往返。
改法：先收集全部 `AwaitApproval(rx)` 并一次性发出所有卡，再并发 await。

**#9/10/11 security.rs**
- `:475` OPTIONS 早退 → 移到 CORS 层之后、鉴权之前，或至少加独立限流
- `:331` `?token=` 接受 → 保留兼容但从 `TraceLayer` 脱敏
- `:581/:600` `api_key` 常量时间比较 → 单行手写比较（不引依赖，符合六步阶梯第 2 条）

**#12 密钥文件权限** — `channels/mod.rs:79` / `tls.rs:210`
裸 `fs::write` → 加权限收紧。仓库已有正确范式 `crash_dump.rs:273 set_permissions(0o644)`。

**#13 CI gate** — `scripts/ci-gate.sh`
第 7 步 2500 行告警是 advisory → 升级为阻断；新增 `#[ignore]` 计数检查。

## 明确不做（附理由）

- **#3 provider 429/5xx 零重试** — 报告推翻。`llm_retry.rs:159` 有真重试循环（默认 3 次 + jittered_backoff），`classify_error` 把 429 和 5xx 都路由进去。残留真问题仅：`retry-after` 只作下次请求闸门，从不作本次退避时长。**可选优化，非缺陷。**
- **#4 sub_agent 不 abort** — 报告高估。协作式 interrupt 存在且被观测，token 燃烧限住约一次 LLM 调用。真缺陷是工具路径缺检查（已收进 P2 #7）。
- **配对错误预算全局共享** — 有意设计且 `pairing.rs:52` 有注释说明。6 位码空间下 5 次上限是唯一暴力破解防线，改成按 IP 会降低安全性。**需产品决策，不擅自改。**
- **10 万行目标** — 与项目现实脱节。22 crate / 30+ 工具后端 / 多 provider / MCP / CUA / 语音 / IM / TLS 配对，27 万行是合理体量。AGENTS.md 自身"10 万行"与开头"18 crates, ~200K lines"自相矛盾。**建议改为：禁止新增上帝文件 + 拆 local_agent_service.rs，而非全局行数配额。** 真正冗余是平行复制（`send_message`/`send_message_stream` 共享 ~300 行，`local_agent_service.rs:1360` TODO 自陈），不是总量。

### 顺带修掉的预存在失败

`hermix-environments` 的 `test_file_exists` 硬编码 `/tmp` —— 项目是
Windows-only，`/tmp` 不存在，该测试**每次跑必失败**。改用
`std::env::temp_dir()`。（首次 `cargo check` 通过是因为该修改发生在
check 之后；`--all-targets` 现在已覆盖。）

### 关于 hermix-plugin 的偶发失败

全量 `cargo test --workspace` 时 `validate_reports_precise_js_location`
失败一次。用 `git stash` 在**干净树**上单独跑该测试：**通过**；恢复我的
改动后再跑：**同样通过**。故该失败是全量并发执行下的偶发（esbuild 子
进程/控制台编码相关），**与本次改动无关**——本次改动未触及
`hermix-plugin` 任何文件。
