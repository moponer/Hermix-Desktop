内核很小，其余都是插件

Context（服务注册）/ Session（append-only 事件日志）/ Seams（trait 接缝）/ Boot（profile 组合）四件加起来五千多行，剩下的都是插件——连 agent loop 都是：跑一轮只返回 CallModel / ExecuteTools / Finish / Suspend 四个指令之一，它自己不能提交、碰不到数据库和连接，随时可中断。

不变量有断言守着：任何进到模型请求里的内容，都必须能从日志重建。MCP 默认不编译、不启动，插件才是扩展的默认方式。

怎么干活

大活派给子代理
大文件、长 PDF、长命令输出、批量网页、一次扫二十几个文件——体量超过阈值且不中途分支的任务，派给子代理干。子代理读完只回结论，主上下文不长胖。
压缩不删东西
到阈值压一次。折掉的轮次作为真实消息行搬进子会话，原会话一行不动，摘要只当索引用。界面上看得到压过几次、折了多少轮。
终端有记忆
走 ConPTY 的持久会话，命令之间状态连续（cd、环境变量、REPL 都留着），输出里的转义序列先剥干净再给你看。
浏览器控制走进程内 CDP
用 WebView2 自带的 DevTools 协议，不开 remote debugging 端口，也不用额外分发一套 Chromium。实测可拿到 184 个无障碍节点。
审批只在越界时问
启动时按 profile 划一次边界，边界内直接放行，越界才拦。Windows 上还叠了四层：受限令牌、Job Object（限内存 / CPU / 进程数）、低完整性 AppContainer，可选 WSL2 后端。
记忆会过期
事实按 TTL 分层，对话回放帧 14 天、会话尾注 30 天衰减，置顶的永不衰减，重复写在入口就拦掉。设置里有记忆图谱，能查、能固定、能隐藏。
文件索引挑便宜的路
启动走 MFT/USN，几秒建完。helper 不可用就留空，不退化为全盘遍历——自动干的活只做便宜的。你真的打开查找面板，才允许兜底扫。单卷卡死有看门狗，能带着已扫到的结果退出。
说出来就能用的应用
一句话生成多文件前端工程（vanilla HTML/CSS/JS），开发模式热跑，一键打成单个 exe：资源嵌进 PE 资源节，运行期虚拟协议内存直喂，跑起来不需要联网取资源。

装在你机器上的样子

没有安装器向导，也没有后台常驻。

一个 exe
解压即用，不装系统服务、不写注册表。要卸载就删文件夹，不留残余。
一个文件
全部数据落在一个 SQLite 文件里。备份就是复制这个文件，换机器就是搬这个文件。
一条通道
界面与本地服务走 stdio 直连，不开监听端口。外部进程扫不到它在通信。
