车队合规监控 + 自动发报文

监控员打开就看得到车队实时状态与合规档位，识别违规动车并自动下发提示报文，路单接入与历史归档也在同一个界面里。Rust 后端 + React 19 前端，便携 zip 解压即用。

能做什么

双源 GPS
两套平台并行，5 秒一轮；总览弹窗走 fresh 通道，绕过 90 秒缓存。
四档合规判定
按车号 + 路单 + 报备三态组合：T1 路单生效、T2 报备在期、T3 无手续，T0 是报备前置。
路单核验
报送平台的数据走 SM2（C1C3C2）解密。路单只录入还没生效时，先查报备；没有报备才判违规动车。
报文下发
T3 违规动车启程那一刻触发一次，不是持续告警。带去重、TTL、失败计数，还有一道防误发复核闸。
失联能降级
GPS / 路单 / 平台事件三路心跳。路单断了就退回纯 GPS 判定，恢复后自动停运。
历史归档
SQLite 双表留 7 天，预警和报文分开存，车牌支持模糊和后 N 位检索。
对外接口
内置无鉴权 HTTP 端口，别的系统可以直接拉快照、预警、报文。只监听本机。
界面内更新
纯 Rust 四段：下载 → 校验 SHA → 改名交换 → 启新进程 → 确认存活。失败回滚，成功清 temp。带进度条，不弹黑窗口。

四档怎么判

合规不是「有手续 / 没手续」两个状态。真实业务里有四种，判错任何一种都会造成误报或漏报。

T1
路单已生效，正常营运
T2
没有路单，但报备在有效期内
T3
既无路单也无报备，属于违规动车
T0
报备前置状态，还没进入判定链

最容易出错的地方是「已录入但未生效」：只看有没有记录会把未生效当成无效，进而误判成违规。所以顺序是先查报备，确实没有才判违规。

轻、快、稳

快
GPS 五秒一轮，首屏八路并发一起评估，不用排队等；总览弹窗绕过缓存，取的是当下这一刻。
稳
GPS、路单、平台三路心跳。路单断了就退回纯 GPS 判定，恢复后自动停运，不会一直误报。
轻
便携 zip 解压即用，不装系统服务。历史只留七天，到期自动清，硬盘不越用越沉。
