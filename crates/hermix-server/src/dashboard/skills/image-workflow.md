# 图片生成与处理

## 工具接线

- **文生图**：`gpt_image`（prompt + size/quality/background）。
- **改图**：`gpt_image` 带 `input_image` 参考图做编辑——**不重新生成**
  （用户要的是"这张图改一下"，不是"再来一张类似的"）。
- **备选生图**：`image_gen`（gpt_image 不可用时的回退）。
- **格式转换/压缩**：`file_converter`（png/jpg/webp/bmp/gif 互转、图转 PDF）。
- **看图**：`read_image`——分析类任务**在 `delegate_task` 内**执行
  （每张图 2000-8000 token，进主上下文永久付费）；用户当前消息**粘贴/附带**
  的图已是多模态上下文，直接分析，无需工具。
- **批量**（≥ 3 张）：`delegate_task` 分批，每批 3-5 张，批次间汇总。

## 生图提示词纪律

结构四要素：**主体（是什么/在做什么）+ 风格（写实/插画/像素/摄影术语）+
构图（视角/景别/留白）+ 约束（不要什么、画幅比例）**。用户给的描述先补全
缺的要素再调工具；生成后如实展示结果，效果不符时修改提示词重试，最多
两轮，仍不符就问用户想要哪方面调整。

## 流程纪律

1. **产物留路径**：生成/转换后的文件给完整路径，说明格式与尺寸。
2. **改图先确认改什么**：局部重绘/风格迁移/换背景/加元素是四种操作，
   拿不准先问一句。
3. **转换无损优先**：png→jpg 有损，先问是否接受；webp 兼容性存疑的
   场景（老系统）默认转 png。

## 反例（不要这样做）

- ❌ 用户要"改这张图"却重新生成一张——参考图编辑才保得住原构图
- ❌ 主上下文直接 read_image 十张图——ctx 永久膨胀，必须 delegate
- ❌ 无损格式直接转有损不问一声
- ❌ 提示词只写"一张好看的图"——四要素缺三

## 输出契约

生成/编辑类：结果文件路径 + 用的提示词（可复现）+ 尺寸格式。
批量类：逐张清单（原文件 → 结果文件）+ 失败项及原因。遵循系统提示
REPORT_SECTIONING 分节规则。
