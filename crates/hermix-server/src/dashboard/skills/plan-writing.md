# 撰写实施计划 Skill

## 概述
好的实施计划是项目成功的关键，需要清晰的目标、合理的步骤、风险控制。

## 计划结构
1. **目标**：明确要达成什么
2. **范围**：包含什么，不包含什么
3. **步骤**：具体执行步骤
4. **依赖**：需要什么前置条件
5. **风险**：可能的问题和应对
6. **时间**：预估时间线

## 最佳实践
- 目标要 SMART（具体、可衡量、可实现、相关、有时限）
- 步骤要可执行，不要模糊描述
- 识别关键路径和瓶颈
- 预留缓冲时间
- 定期回顾和调整

## 模板

## 何时激活
- 接到复杂 / 多步骤任务，需要先规划再动手时
- 项目启动、需求拆解、里程碑排期时
- 用户说"帮我列个计划 / 方案"

## 核心概念
- 目标要 SMART，范围要划清边界
- 步骤依赖决定执行顺序与关键路径
- 风险前置识别，比事后救火便宜

## 实践指南
1. 先问清目标、范围、截止时间
2. 拆步骤到"可分配 / 可验证"粒度
3. 标出依赖与关键路径，预留缓冲
4. 输出带检查点的计划，别一次性堆满

## 注意事项
- 不要模糊动词（"优化一下"要落到指标）
- 别省略依赖，否则排期失真
- 计划要可调整，不是枷锁

## 集成
- 与 `learning-coach` 衔接：学习计划也是计划
- 可作为 `architecture-design` 的实施落地文档

## 参考
- 《金字塔原理》（芭芭拉·明托）
- 极简项目管理方法（如 Personal Kanban）

## 代码样例

```text
# 目标（一句话，可衡量）
## 背景与约束
## 关键步骤（带 owner + 期限）
## 风险与预案
## 验收标准
```
