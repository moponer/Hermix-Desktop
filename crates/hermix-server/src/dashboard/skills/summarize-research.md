# 多材料摘要研究

## 工具接线

1. **单份短材料**（< 20 页文本型）：`markitdown` 直接转 Markdown 读。
2. **长文档 / PDF / 图片型 PDF**：走 `delegate_task`（Explore 角色），
   context 给路径，task 写明"返回：一句话主旨 + 5 条以内要点 + 关键数据
   与出处页码"。禁止在主上下文直接读 100 页文档。
3. **网页**：`web_extract` 抓正文；抓取失败换 `browser_navigate` +
   `browser_snapshot`（需用户已开启 browser 工具集）。
4. **扫描件（markitdown 输出空/乱）**：走 `read_image`（在子代理内）交
   视觉模型。

## 流程纪律

1. **先列材料清单**：对每份材料给一行身份（文件名/URL + 页数/字数），
   确认无遗漏再开工。
2. **逐份三句摘要**：每份材料先独立产出 ≤ 3 句核心摘要 + 关键数据，
   然后才做对比——防止只总结第一份就交差。
3. **交叉对比**：只在"多份材料"任务中做；对比维度先定（观点差异/数据冲突/
   互补信息），不硬凑表格。
4. **溯源**：每个事实性结论标注来自哪份材料哪一节/页；材料间矛盾的地方
   明确指出并列出双方原文位置，不自行裁决谁对（除非用户要求仲裁）。

## 反例（不要这样做）

- ❌ 只总结第一份材料就输出——清单上有几份就处理几份
- ❌ 大段抄原文冒充摘要——摘要是信息压缩，不是搬运
- ❌ 编造材料里没有的结论或数据——拿不准就写"材料未提及"
- ❌ 遗漏页数信息让用户无法溯源

## 输出契约

开头一句话结论 → `## 逐份摘要`（每份一小节）→ `## 对比/综合`（如适用）
→ `## 关键数据与来源`。遵循系统提示 REPORT_SECTIONING 分节规则。
