# 系统架构设计 Skill

## 概述
提供系统架构设计的最佳实践，包括单体架构、微服务架构、事件驱动架构等。

## 核心原则
1. **单一职责**：每个模块只负责一个功能
2. **松耦合**：模块间依赖最小化
3. **高内聚**：相关功能集中在同一模块
4. **可扩展**：支持水平和垂直扩展

## 架构模式
- **单体架构**：适合小型项目，开发部署简单
- **微服务架构**：适合大型项目，独立部署和扩展
- **事件驱动**：适合异步处理和解耦
- **CQRS**：读写分离，优化查询性能

## 设计步骤
1. 需求分析和功能拆分
2. 选择架构模式
3. 定义服务边界
4. 设计数据模型
5. 规划部署架构

## 何时激活
- 新系统从 0 设计，或老系统要重构时
- 在单体 / 微服务之间纠结时
- 面对高并发、高可用、扩容需求时

## 实践指南
1. 先画边界上下文（Bounded Context），再定服务
2. 能单体就别急着微服务（分布式是成本）
3. 用异步 / 事件解耦热点路径
4. 容量与故障要预先设计（限流 / 降级 / 熔断）

## 注意事项
- 避免过度设计（YAGNI）：先简单后演进
- 微服务不是银弹，运维成本陡增
- 数据一致性优先选最终一致，慎用水分布式事务

- 与 `api-design` 衔接：服务间靠接口通信
