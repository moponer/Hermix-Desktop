# 浏览器自动化

前置：browser 工具集未开启时**如实告知**用户去 设置 → 工具集 开启，
不声称"我没有浏览器能力"（系统提示 WEB_AUTOMATION_GUIDANCE 能力地图）。

## 工具接线（核心循环）

```
browser_navigate(url)          → 打开
browser_snapshot()             → 看结构化页面状态（元素、可点项）
browser_click/type/screenshot  → 动作
（循环：动作 → 快照 → 确认生效 → 下一步）
```

- **每步动作前先 `browser_snapshot`** 确认目标元素存在——不快照就点击
  是最高频失败原因（页面没加载完/元素在 iframe/懒加载未触发）。
- 填表前确认字段语义（"姓名"填姓还是全名、日期格式 YYYY-MM-DD 还是
  MM/DD），有歧义先问或按表单提示文案来。
- `browser_close` 收尾：会话结束或用户不再需要时关闭，不留幽灵窗口。

## 流程纪律

1. **登录态与验证码**：登录信息缺失先要账号密码/验证码，不猜。遇验证码
   按三步走：
   - ① `browser_screenshot` 截下验证码区域；
   - ② **用 `read_image` 读那张图**——你有原生多模态视觉，能直接看图。
     普通数字/字母码：读出后填入 `browser_type`，提交前让用户核对一次；
   - ③ 读不清（滑块/点选/严重扭曲/算式图）→ 请用户看浏览器小窗里的
     实时画面，口头报码给你填。**不要**声称"视觉识别失败"然后给泛泛
     建议，**不要**尝试绕过验证码（找接口/测试号是备选路径，先如实
     说明现状再建议）。
2. **提交类操作（下单/付款/删除/发送）是最后一步**：提交前
   `browser_screenshot` 留证，向用户复述即将提交的内容，不可逆操作必须
   用户明确确认过才执行。
3. **等待与重试**：动作后页面无反应 = 重 snapshot 确认，而不是重复点击。
   同一元素连续失败两次 → 换选择器/换路径（如从"点按钮"改为"回车提交"），
   不原样重试第三次。
4. **抓数据**：结构化数据优先从 snapshot 提取，截图只作留证；多页数据
   逐页翻页抓取并记录页码。

## 反例（不要这样做）

- ❌ navigate 后立刻 click——没 snapshot 确认加载完成
- ❌ 点击后不看结果就报成功
- ❌ 重复点击同一失效按钮三次
- ❌ 替用户提交不可逆表单而不事先确认内容

## 输出契约

操作类：逐步回执（做了什么、页面当前状态、有无异常）+ 任务完成时的
最终截图路径。抓取类：数据 + 来源页码/URL + 抓取时间。遵循系统提示
REPORT_SECTIONING 分节规则。
